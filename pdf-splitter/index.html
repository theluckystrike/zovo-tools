About This PDF Splitter

This tool splits PDF files entirely in your browser. It reads the raw binary data of your PDF, parses the internal structure to locate each page, and reconstructs valid single-page or multi-page PDFs from the original objects. No server is involved at any point.

You can extract a single page, a custom range like "1-5, 8, 10-12", split into one PDF per page, or group pages in sets of N. After uploading, page thumbnails appear in a grid that you can reorder by dragging. The split operation respects your custom order.

Once splitting is complete, download each resulting PDF individually or grab everything at once as a ZIP file. The ZIP is also built from scratch in JavaScript — no external libraries involved.

How PDF Parsing Works

A PDF file is structured around numbered objects, a cross-reference table (xref), and a trailer. This tool reads each of those components to understand where pages live inside the file.

  • Header: The first line declares the PDF version (e.g., %PDF-1.4). This tells the parser which features to expect.
  • Cross-Reference Table: Near the end of the file, the xref table maps each object number to its byte offset. The parser reads this to locate any object on demand without scanning the entire file.
  • Trailer: Right after the xref, the trailer dictionary points to the root catalog object and optionally an info dictionary with metadata (title, author, creation date).
  • Catalog and Pages Tree: The root catalog contains a reference to the Pages tree, which is a hierarchy of page objects. Each page object defines its media box (dimensions), content streams (the drawing commands), and resources (fonts, images).

To extract a page, the parser copies the page object and all objects it references (content streams, fonts, images) into a new PDF with its own xref table and trailer. The result is a valid, self-contained PDF file.

For more on PDF internals, see the Wikipedia article on the PDF format.

Split Modes Explained

Extract Single Page takes one page number and produces one PDF containing only that page. Useful for pulling out a specific form, certificate, or receipt from a larger document.

Extract Page Range accepts a comma-separated list of ranges and individual pages. For example, "1-5, 8, 10-12" extracts pages 1 through 5, page 8, and pages 10 through 12 into a single output PDF. This is the most flexible mode for custom selections.

Split Into Individual Pages creates one PDF per page. A 20-page document becomes 20 separate files. Combined with the ZIP download, this is the fastest way to break a document into its smallest units.

Split Every N Pages groups consecutive pages. If you set N to 5, a 20-page document produces 4 PDFs of 5 pages each. Useful for splitting books into chapters of roughly equal length, or dividing a large manual into sections.

Page Reordering

After your PDF loads, each page appears as a thumbnail card in a grid. You can drag any card and drop it at a new position to change the page order. The split operation uses whatever order you set, so you can rearrange pages before extracting.

This is particularly useful when you want to reorganize a scanned document, move an appendix to the front, or group related pages together before splitting. The reordering is purely visual and does not modify your original file.

ZIP File Builder

When you click "Download All as ZIP," the tool constructs a valid ZIP archive entirely in JavaScript. It writes local file headers for each PDF, followed by the central directory and end-of-central-directory record — the three components every ZIP reader expects.

Each file entry uses the stored (no compression) method, since PDF files are already compressed internally. The CRC-32 checksum is calculated for each entry to ensure integrity. The result is a standard ZIP file that opens in any archive utility or operating system file manager.

For details on the ZIP specification, see the Wikipedia article on ZIP file format.

Technical Details and Limits

The parser handles standard xref tables as used by the vast majority of PDF generators. PDFs with linearized (web-optimized) structures, incremental updates, and multiple xref sections are supported by following the /Prev chain in trailers.

Cross-reference streams (a compressed alternative introduced in PDF 1.5) are supported at a basic level. The parser decompresses FlateDecode streams to read xref data when a traditional table is not present.

Encrypted PDFs are not supported — the parser cannot decrypt protected content. If you need to split a password-protected PDF, remove the password first using a dedicated PDF decryption tool.

Browser Compatibility: This tool works in Chrome 80+, Firefox 78+, Safari 14+, and Edge 80+. It uses the File API, ArrayBuffer, DataView, and the DecompressionStream API (with fallback) for handling compressed content. Internet Explorer is not supported.
Privacy Note: Your PDF files are processed entirely in your browser. Nothing is uploaded to any server. No analytics track your file contents. The tool works offline after the page loads. Close the tab and all data is gone.

Frequently Asked Questions

How does this PDF splitter work without uploading my file?

This tool parses the PDF binary format directly in your browser using JavaScript. It reads the cross-reference table, locates page objects, and reconstructs valid PDFs by copying the necessary objects. Everything runs locally — your file never leaves your device.

What split modes are available?

You can extract a single page by number, extract a custom range (e.g. "1-5, 8, 10-12"), split into individual one-page files, or split every N pages. All modes produce valid PDF files you can download individually or as a ZIP.

Can I reorder pages before splitting?

Yes. After uploading, drag and drop the page thumbnails to rearrange them. The split operation uses your custom order, so you can reorganize before extracting.

What PDF types are supported?

This tool supports standard PDFs with traditional cross-reference tables. Most PDFs from scanners, word processors, and standard generators work well. Heavily encrypted or non-standard compressed PDFs may not parse correctly.

Is there a file size limit?

No hard limit, but performance depends on your browser and available memory. PDFs under 100 MB process smoothly. Larger files may be slower on devices with limited RAM.
