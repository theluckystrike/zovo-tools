How Epoch Time Works

Unix epoch time is a system for tracking time as a running count of seconds. The count starts at the "Unix Epoch" — January 1, 1970 at 00:00:00 UTC. Every second after that point adds 1 to the counter. Right now, we are well past 1.7 billion seconds since that starting point.

Why use epoch time? Computers find it much simpler to store and compare a single integer than a formatted date string. There are no timezone ambiguities, no daylight saving complications, and sorting by time is just sorting numbers. Databases, APIs, log files, and operating systems all use epoch time internally.

Seconds vs. Milliseconds: The original Unix specification uses seconds, giving 10-digit numbers for current dates. However, many modern systems (JavaScript, Java, some APIs) use milliseconds for finer precision, producing 13-digit numbers. If you see a 13-digit timestamp, divide by 1,000 to get standard seconds.

The Year 2038 Problem: Systems that store epoch time as a signed 32-bit integer will overflow on January 19, 2038 at 03:14:07 UTC. The maximum value is 2,147,483,647 (2^31 - 1). After that, the number wraps to negative, which could be interpreted as December 1901. Modern 64-bit systems have already solved this by using 64-bit integers, which will not overflow for another 292 billion years.

Leap seconds are not counted in Unix time. When a leap second is added (as occasionally determined by the IERS), the Unix timestamp either repeats a second or skips ahead, depending on the implementation. POSIX specifies that each day is treated as exactly 86,400 seconds.

For a thorough explanation, see the Wikipedia article on Unix time.

Frequently Asked Questions

What is epoch time (Unix time)?

Epoch time counts the number of seconds since January 1, 1970 00:00:00 UTC. It is the standard way computers store and compare time internally. The value is always in UTC and is not affected by timezones or daylight saving changes.

How do I convert epoch time to a human-readable date?

Enter the epoch timestamp in the converter above, select your timezone, and the result appears instantly. In code: JavaScript uses new Date(epoch * 1000), Python uses datetime.fromtimestamp(epoch), and most languages have similar built-in functions.

What is the difference between epoch seconds and milliseconds?

Standard Unix time uses seconds (10 digits for current dates). Many APIs and languages like JavaScript use milliseconds (13 digits). If your timestamp is 13 digits, it is in milliseconds — divide by 1,000 to get seconds. This tool supports both formats and can auto-detect.

What happens in 2038?

32-bit systems storing Unix time as a signed integer will overflow on January 19, 2038 at 03:14:07 UTC. Modern 64-bit systems are not affected. Most current software and operating systems have already migrated to 64-bit time representations.

Is epoch time affected by timezones?

No. Epoch time is always based on UTC and represents a single absolute moment in time. Timezone differences only come into play when you convert the epoch value to a local date and time string for display purposes.
