ICO (file format) is an image file format for computer icons in Microsoft Windows. How the ICO Binary Format Actually Works

Understanding the ICO file format at the binary level helps explain why this converter produces correct output while many others don't. The ICO format consists of three main structures that must be written in exact byte order:

  1. ICONDIR (6 bytes): The file header starts with a reserved field (2 bytes, must be zero), followed by the image type (2 bytes, must be 1 for ICO, 2 for CUR cursor files), and the number of images in the file (2 bytes). This header tells the OS how many icon sizes are contained in the file.
  2. ICONDIRENTRY (16 bytes each): For each image size, there's a directory entry containing: width (1 byte, 0 means 256), height (1 byte, 0 means 256), color count (1 byte, 0 for 256+ colors), reserved byte (must be 0), color planes (2 bytes), bits per pixel (2 bytes), image data size (4 bytes), and offset to image data from the start of the file (4 bytes).
  3. The actual pixel data for each size. In BMP-based ICO files, this is a DIB (Device Independent Bitmap) header followed by pixel data in bottom-up row order with 32-bit BGRA color values. The DIB header specifies the bitmap dimensions as double the actual height (to account for the AND mask in the legacy format).

This converter uses the Canvas API to resize your source image to each selected size, extracts RGBA pixel data using getImageData(), converts it to the BGRA byte order that ICO requires (swapping red and blue channels), and writes the complete binary structure using DataView and ArrayBuffer. The result is a standards-compliant ICO file that works everywhere - not a hack or a renamed PNG.

Why You Still Need ICO Files in 2026

You might wonder if ICO is still relevant when modern browsers can use PNG and SVG favicons. yes, ICO still matters, and here's why. While modern browsers like Chrome 134, Firefox, Safari, and Edge all support PNG favicons via the <link rel="icon" type="image/png"> tag, there are several scenarios where ICO remains necessary:

  • Legacy browser support: Older browsers and some enterprise environments still look for /favicon.ico at the root of a domain. Without it, they show a default or broken icon.
  • If you're creating icons for Windows applications, executables, or shortcuts, the ICO format is required. Windows doesn't use PNG for desktop icons.
  • Bookmark and tab icons: Some browsers and bookmark managers still prefer ICO when both formats are available, especially when the ICO file contains multiple sizes.
  • Multi-size convenience: ICO is the only format that bundles multiple icon sizes in a single file. Instead of serving separate 16x16 and 32x32 PNGs, one ICO file handles both.
  • Google and other search engines look for /favicon.ico specifically when rendering search results with site icons. Having it available ensures your brand icon appears correctly in search results.

The best practice in 2026 is to provide both: an ICO file at /favicon.ico for maximum compatibility and PNG/SVG alternatives declared in your HTML head for modern browsers. This ico converter handles the ICO side of that equation.

Choosing the Right Sizes for Your Favicon ICO

Not all icon sizes are created equal, and including every possible size makes your ICO file unnecessarily large. Based on our testing across platforms and browsers, here are my recommendations for which sizes to include depending on your use case:

  • Minimum viable favicon (web only): 16x16 + 32x32. This covers browser tabs (16px) and high-DPI browser tabs (32px). about 2-5KB.
  • Recommended website favicon: 16x16 + 32x32 + 48x48. Adding 48px covers Windows taskbar and some bookmark views. about 5-10KB.
  • favicon: 16x16 + 32x32 + 48x48 + 64x64. The 64px version is used by some RSS readers and older versions of Internet Explorer for "pinned sites."
  • Windows application icon: 16x16 + 32x32 + 48x48 + 256x256. Windows Explorer uses 256x256 for the large icon view. The jump from 48 to 256 is intentional - Windows scales intermediate sizes from the nearest available.
  • All six sizes (16, 32, 48, 64, 128, 256). Only necessary if you're creating icons for specialized software or kiosk applications. The resulting ICO file can be 50-200KB.

I've found that the "recommended" tier (16 + 32 + 48) provides the best balance of compatibility and file size for web projects. Don't overthink it - start there and add larger sizes only if you have a specific need.

Source Image Best Practices

The quality of your ICO output depends heavily on the quality of your source image. Here are guidelines I've developed from our testing with thousands of icon conversions:

  • Start with a large source: Use a source image that's at least 256x256 pixels. Scaling down produces better results than scaling up. Ideally, start with a 512x512 or 1024x1024 master icon.
  • Use If your icon needs a transparent background (most do), use a PNG source with an alpha channel. JPG doesn't support transparency and will fill transparent areas with white or black. WebP with alpha also works.
  • Square images work best: The ICO format requires square dimensions. If you upload a non-square image, this converter will scale it to fit within the square canvas while maintaining aspect ratio. For best results, crop your image to a 1:1 ratio before uploading.
  • Simple designs scale better: Complex photographs and detailed illustrations lose important details at 16x16 pixels. The best favicons use simple shapes, bold colors, and high contrast. I tested logo designs with fine lines and found they become unreadable below 32x32.
  • Use the preview grid this converter provides to evaluate how your icon looks at each target size. If the 16x16 version is illegible, consider using a simplified version of your design for the smaller sizes.

Client-Side ICO Generation The Technical Approach

This converter runs entirely in your browser using standard Web APIs. No server uploads, no external dependencies beyond the page itself. Here's how the conversion pipeline works technically:

  1. When you select or drop an image, we create a new Image object and load it via a FileReader-generated data URL. This triggers the browser's native image decoder for PNG, JPG, or WebP.
  2. For each selected output size, we create an HTML Canvas element at the target dimensions and draw the source image onto it using drawImage() with bilinear interpolation (the browser's default scaling algorithm). This produces smooth, anti-aliased results at every size.
  3. We use getImageData() to read the RGBA pixel array from each canvas. This gives us a flat Uint8ClampedArray of 4 bytes per pixel (red, green, blue, alpha).
  4. The ICO format stores pixel data in BGRA order (blue first, then green, red, alpha). We swap the red and blue channels and flip the row order from top-down to bottom-up as the BMP specification requires.
  5. Using ArrayBuffer and DataView, we write the ICONDIR header, all ICONDIRENTRY structures, and the bitmap data blocks in the correct byte order. Little-endian encoding is used throughout, matching the Windows binary format conventions.
  6. The completed ArrayBuffer is wrapped in a Blob with MIME type image/x-icon and made available for download via URL.createObjectURL().

The entire process takes milliseconds for typical icon sizes. Even generating all six sizes from a 1024x1024 source image completes in under 100ms on Chrome 130 or newer. The PageSpeed impact is zero during initial page load since no conversion code runs until user interaction.

Common Mistakes When Creating Favicons

Through our testing and user feedback, I've identified the most common mistakes people make when creating favicons. Avoid these pitfalls:

  1. Renaming a PNG to.ico: This doesn't create a valid ICO file. Windows won't use it as a desktop icon and some browsers will show a broken icon. Always use a proper converter.
  2. A 16x16-only favicon looks blurry on high-DPI displays. Always include at least 16x16 and 32x32.
  3. Non-transparent favicons look out of place on dark browser themes. Use PNG sources with alpha channels.
  4. Complex source images: Detailed illustrations become illegible at 16x16. I found that the best favicons use 2-3 colors, bold shapes, and high contrast.
  5. Forgetting the root favicon.ico: Many crawlers request /favicon.ico directly. Without it, you'll get 404 errors and missing icons in search results.
  6. Not testing across browsers: Icons can render differently in Chrome, Safari, Firefox, and Edge due to different scaling algorithms. Always test at actual size.

Frequently Asked Questions

What exactly is an ICO file and why do I need one?

ICO is the image file format used for icons on Microsoft Windows and as favicons (the small icons in browser tabs) on websites. Unlike PNG or JPG, an ICO file can contain multiple image sizes bundled together - for example, 16x16 for browser tabs and 32x32 for high-DPI displays - in a single file. You need one because browsers and operating systems look for /favicon.ico by default, and without it, your site or application won't display a proper icon in tabs, bookmarks, or search results.

All processing happens in your browser using the Canvas API, so there are zero server costs for me to pass along to users.

What image formats can I convert to ICO?

You can convert PNG, JPG/JPEG, and WebP images to ICO format. PNG is the recommended source format because it supports transparency (alpha channel), which is preserved in the ICO output. JPG images work but don't support transparency, so transparent areas will be filled with the background color. WebP with alpha transparency is also fully supported.

Which sizes should I select for a website favicon?

For a standard website, select at least 16x16 and 32x32. This covers regular and high-DPI browser tabs. Adding 48x48 is recommended for Windows taskbar visibility. If you need Windows desktop application icons, add 256x256 as well. I've found that the 16 + 32 + 48 combination provides the best balance of compatibility and file size for most web projects.

Does the converter preserve image transparency?

Yes. If your source image is a PNG or WebP with an alpha channel, the transparency is fully preserved in the ICO output. The converter uses 32-bit BGRA pixel data which includes full 8-bit alpha channel support. The transparency preview in the grid shows a checkerboard pattern where transparent areas exist, so you can verify before downloading.

Are my images uploaded to any server during conversion?

not. All image processing happens locally in your browser tab using the Canvas API, FileReader, DataView, and Blob APIs. Your images never leave your device under any circumstance. You can verify this yourself by opening your browser's Network tab in developer tools before converting - you'll see zero outbound requests containing your image data. The tool even works if you disconnect from the internet after loading the page.

It relies on the Canvas API, DataView, ArrayBuffer, and Blob API - all of which have been supported in major browsers for years. Internet Explorer is not supported.
