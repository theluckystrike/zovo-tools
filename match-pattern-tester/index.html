Match pattern tester

By Michael Lip. Updated 2026-10-10.

Type a Chrome extension match pattern and a URL. The page tells you if the pattern matches the URL, and which part decided the result: the scheme, the host, the port or the path. It also tells you why a pattern is invalid.

The tool tests the documented match pattern syntax of Google's match patterns page (read 2026-10-10). It does not test exclude_matches, globs (include_globs, exclude_globs) or declarativeNetRequest filters. The test runs in your browser.

The documentation shows some patterns in two forms, for example https://*/* or https://*/. It also says: "For host permissions, the path is required but ignored." This tester always compares the path, as the function MatchesURL in Chromium's url_pattern.cc does (read 2026-10-10). Thus the short form https://*/ matches only the root path / in this tester. Use the form with /* to match all paths.

The rules that the tester applies

The documentation gives the structure of a match pattern as <scheme>://<host>:<port>/<path>. The port is optional. The sources below were read on 2026-10-10.

Patterns that are invalid

  • https://example.com has no path. Write https://example.com/*.
  • https://www.google.*/* has a wildcard that is not the first character of the host. The documentation says that Chrome does not support match patterns for top-level domains. Write one pattern for each domain, as in http://google.es/* and http://google.fr/*.
  • https://*foo.example.com/* has a wildcard that a period does not follow. Write https://*.example.com/*.
  • file://foo* has two slashes. Write file:///foo*.
  • ftp://example.com/* has a scheme that the documentation does not list.

Limits of this tester

Is this the code that Chrome runs?

No. The tester is a separate JavaScript implementation of the documented rules. Chromium's parser in url_pattern.cc (read 2026-10-10) knows more schemes than the documentation lists, for example ftp, ws, wss and data. It has special handling for filesystem URLs. It also accepts a file pattern that has a host. The tester does not cover these cases. For an unusual host name or an unusual percent-escape, the result can differ from Chrome.

Where does a manifest use match patterns?

The documentation names these uses: to inject content scripts, to declare host permissions, to grant access to web-accessible resources, and in the externally_connectable.matches manifest key. Google's Declare permissions page (read 2026-10-10) says that a change of the match patterns in host_permissions or content_scripts.matches triggers a warning. To see the host patterns of a packed extension, open it in the CRX viewer. To check the icon, screenshots and promo tiles of a store listing, use the Chrome Web Store image size checker. To check a keyboard shortcut in the manifest's commands block, use the keyboard shortcut checker.

Does the query string take part in the match?

Yes. The pattern https://example.com/foo does not match https://example.com/foo?x=1. The pattern https://example.com/foo* matches it. The fragment does not take part.
