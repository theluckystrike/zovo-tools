Chrome extension keyboard shortcut checker

By Michael Lip. Updated 2026-10-31.

Paste the manifest.json of your extension, or only its "commands" object. The checker reads each suggested_key the way Chromium's manifest parser does. For each command it shows Pass or Fail on Windows, macOS, Linux and ChromeOS. For each Fail it shows the error text that Chromium uses. It also lists commands that suggest the same shortcut, and it counts the shortcuts toward the limit of 4.

The check runs in your browser. The checker does not send your text over the network. A Pass means that the parser accepts the commands block. It does not mean that Chrome will assign each shortcut (see Limits). The rules come from Chromium source files at commit aa08c55 and from the commands reference page on developer.chrome.com (see Sources). Where the two do not agree, the checker follows the source.

Why four systems? Chrome checks the commands block on the system it runs on, and some rules depend on that system. For example, "chromeos": "Ctrl+Shift+Search+Y" passes on ChromeOS. On Windows, macOS and Linux the same entry stops the extension from loading, because there a shortcut can have only 3 parts.

How the checker decides


    

  • Input. Chrome reads manifest.json with options that allow // and /* */ comments, line breaks inside strings and \xNN escapes, but not a comma after the last item (file_util.cc line 335, json_file_value_serializer.h line 66, json_reader.h lines 50-84). The checker accepts the same three extensions to strict JSON. It treats the text as a whole manifest when it has a manifest_version key, or a "commands" key whose value does not look like a single command. Otherwise it treats the text as the "commands" object itself. A manifest without a "commands" key is valid. An empty "commands" object is valid too.
    • 

  • Four systems. Chromium picks the entry for the system it runs on (windows, mac, linux or chromeos). When that entry is missing, it uses default. The checker runs the parser once for each of the four systems.
    • 

  • Every entry counts. Chromium parses every entry of suggested_key on every system. An error in the mac entry also stops the extension from loading on Windows.
    • 

  • First error. Chrome stops at the first error in the commands block and reports only that error. The checker checks every command and every entry. It then marks the error that Chrome reports first on each system.
    • 

  • The limit of 4. On each system the checker counts the commands whose shortcut is not a media key. Action commands such as _execute_action count too. A fifth counted command is a Fail.
    • 

  • Conflicts. Two commands conflict when they give the same key combination on the same system. The order of the keys does not matter: Shift+Ctrl+Y is the same as Ctrl+Shift+Y. A conflict is not a Fail. Chrome loads the extension, but it does not assign the shortcut to the second command in its order (named commands in name order, then action commands).
    •

Limits of this checker


This tool checks the manifest only. It does not know the shortcuts of the browser or of other extensions, and Chrome can ignore a suggested key that another extension already uses.


The commands reference page says: "Certain operating system and Chrome shortcuts (e.g. window management) always take priority over Extension command shortcuts and cannot be overridden."


What does the checker not test?

    

  • Chrome's own shortcuts. Chrome does not assign a suggested key of a command that is not global when the key is a Chrome shortcut. The list of those shortcuts is not in the fetched files.
    • 

  • Shortcuts that the user changed at chrome://extensions/shortcuts.
    • 

  • The kCommandsAccessibility permission that lifts the limit of 4. The fetched files do not show which manifest entry grants it.
    • 

  • The documentation's sentence that ChromeOS does not support global commands.
    • 

  • The other keys of the manifest.
    • 

  • Rare JSON cases that Chrome rejects but this checker accepts: nesting of 200 or more levels of objects and arrays, and lone surrogate escapes (such as "\uD800").
    • 



Why can the number in commands[N] differ from Chrome?

Chromium numbers the commands in the order that it reads them. The checker numbers them in name order. The fetched files do not show the order that Chromium uses. So the number in an error, and the error that Chrome reports first when several commands fail, can differ. The result Pass or Fail for each system does not depend on the order.


Does the checker send my manifest anywhere?

No. The checker code has no network calls. It reads your text from the text field and parses it in your browser.


How does key recording work?

Turn on "Record the keys that I press" and press a combination in the shortcut field. On macOS the checker writes the Command key as Command, the Control key as MacCtrl and the Option key as Option, and checks the combination as a mac shortcut. A Ctrl in the default shortcut becomes Command on macOS. On other systems the checker does not record the Windows key or the Search key. The Tab key without Ctrl or Alt still moves the focus, and Escape turns recording off. If a combination does nothing in the field, type it instead.
