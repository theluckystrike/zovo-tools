Every week, I watch people spend hours manually copying data from websites into spreadsheets. Product prices, contact lists, job postings, research tables, real estate listings. The data is right there on the page, but getting it into a usable format feels like it requires a computer science degree. It does not. I have been extracting website data for years, and the vast majority of my scraping work involves zero code. This guide walks through every method I use, from the simplest copy-paste tricks to browser extensions that handle the heavy lifting automatically.

What Web Scraping Actually Is

Web scraping is the process of extracting structured data from websites. That is the entire definition. When you highlight a table on Wikipedia, copy it, and paste it into Excel, you are scraping. When a Python script downloads 10,000 product pages and pulls out prices, that is also scraping. The underlying principle is identical. The only difference is scale and automation.

Every web page you visit is built from HTML, the markup language that defines the structure of content. A product listing has a title inside an <h1> tag, a price inside a <span>, a description inside a <div>, and images inside <img> tags. When you scrape, you are telling your tool (whether it is your fingers, a spreadsheet formula, or a script) which HTML elements contain the data you want, then collecting that data into a structured format like a CSV or spreadsheet.

The key concept is selectors. A CSS selector is a pattern that identifies specific elements on a page. The selector h1 targets every heading. The selector .price targets every element with the class "price." The selector #product-title targets the single element with that ID. Every scraping method, from Google Sheets formulas to Python libraries, uses some form of selector to locate data within a page. Understanding this concept, even at a basic level, makes every extraction method in this guide easier to follow.

There are two broad categories of web pages when it comes to scraping. Static pages deliver all their content in the initial HTML response. The data is right there in the source code. Dynamic pages load their content using JavaScript after the initial page load, pulling data from APIs and rendering it in the browser. Static pages are straightforward to scrape with any method. Dynamic pages require tools that can execute JavaScript, which limits your options but does not eliminate them.

The Legal Side of Web Scraping

Before scraping anything, you need to understand where the legal boundaries are. I am not a lawyer, and this section is not legal advice, but I have spent considerable time researching the precedents and regulations that apply to web scraping in 2026.

The most significant legal ruling in US web scraping law is hiQ Labs v. LinkedIn (2022). The Ninth Circuit Court ruled that scraping publicly available data does not violate the Computer Fraud and Abuse Act (CFAA). This was a major win for data accessibility. The court distinguished between accessing data that is freely available to any browser visitor versus bypassing authentication or technical barriers to access private data. The former is generally permissible. The latter can be a federal crime.

Robots.txt and Its Limitations

Every website can publish a robots.txt file at its root URL (for example, example.com/robots.txt) that tells automated tools which pages they may or may not access. A typical robots.txt file looks like this:

User-agent: *
Disallow: /private/
Disallow: /api/
Allow: /public/
Crawl-delay: 10

Robots.txt is technically a suggestion, not a legal requirement. However, ignoring it weakens your legal position significantly. Courts have considered robots.txt compliance as a factor in scraping disputes. My rule is simple. If robots.txt says stay out, I stay out. The data is either available through other means, or I contact the website owner to request access.

Terms of Service

Many websites include anti-scraping clauses in their Terms of Service. Whether these are legally enforceable varies by jurisdiction and specific circumstances. A ToS violation is generally a breach of contract claim, not a criminal matter. That said, I always check the ToS before running any automated scraping tool against a website. If the ToS explicitly prohibits scraping, I look for alternative data sources or use manual extraction methods that fall well within fair use.

Data Privacy Regulations

GDPR (Europe), CCPA (California), and similar regulations add another layer of complexity when the data you are scraping contains personal information. Names, email addresses, phone numbers, and other personally identifiable information carry additional legal obligations regardless of whether they are publicly visible. If you are scraping personal data, consult with a legal professional about your specific use case and jurisdiction.

| Legal Factor | Status | What It Means for You |

|---|---|---|

| hiQ v. LinkedIn ruling | Public data scraping is not CFAA violation | Scraping public pages is generally permissible in the US |

| robots.txt compliance | Voluntary but legally relevant | Always check and respect robots.txt directives |

| Terms of Service | Contractual, not criminal | Read ToS before scraping; violation may lead to civil claims |

| GDPR and CCPA | Mandatory for personal data | Consult legal counsel before scraping personal information |

| Authentication bypass | Criminal under CFAA | Never bypass login pages or access controls to scrape |

| Rate limiting | Technical and legal signal | Respect rate limits; overwhelming a server can be actionable |

Copy-Paste and Manual Extraction

The simplest scraping method is one you already know. For small datasets (under a few hundred rows), manual copy-paste is faster than setting up any tool. The trick is doing it efficiently.

Tables to Spreadsheets

When a website displays data in an HTML table, you can often select the entire table, copy it, and paste it directly into Google Sheets or Excel. The spreadsheet software recognizes the table structure and places each cell's data into the correct row and column. I use this method at least once a week for quick data grabs from Wikipedia, government data portals, and financial sites.

The technique works best when the table is a genuine HTML <table> element rather than a layout built from <div> tags styled to look like a table. You can tell the difference by right-clicking the table and selecting "Inspect" in Chrome. If you see <table>, <tr>, and <td> tags in the Elements panel, copy-paste will work cleanly. If you see nested <div> elements, the data will likely paste as a single column of text, and you will need a different approach.

Copy-paste table extraction:
Select table on page → Ctrl+C (Cmd+C on Mac)
→ Open Google Sheets → Ctrl+V (Cmd+V on Mac)
→ Data appears in rows and columns

Lists and Repeated Elements

For non-table data like product listings or search results, copy-paste still works but requires more cleanup. I select the entire block of listings, paste into a plain text editor first (to strip formatting), then paste into a spreadsheet. From there, I use the spreadsheet's text-to-columns feature or simple formulas to split the data into proper fields.

Google Sheets has a useful function for this: SPLIT(text, delimiter). If your pasted data has names and prices separated by a consistent character (a dash, a pipe, a tab), SPLIT will separate them into individual cells. Combined with TRIM() to remove extra whitespace, you can clean up manually pasted data in minutes.

PDF Tables

A surprising amount of web data is locked inside PDF files. Government reports, academic papers, financial filings. For these, I copy the table from the PDF viewer and paste into Google Sheets. The results are often messy, but the "Split text to columns" feature under the Data menu (using space or tab as the delimiter) usually gets the data into shape. For more complex PDF tables, Tabula (tabula.technology) is a free tool specifically designed for extracting tables from PDFs.

Tip. When copy-pasting from websites, paste into Google Sheets using Ctrl+Shift+V (Cmd+Shift+V on Mac) to paste as plain text. This avoids bringing over HTML formatting that can break your spreadsheet layout.

Chrome DevTools for Structured Data

Chrome Developer Tools is the most powerful free data extraction tool you already have installed. I use it regularly for extracting data that does not copy-paste cleanly, inspecting the structure of pages before choosing a scraping method, and pulling data from dynamic pages that load content via JavaScript.

Inspecting Page Structure

Right-click any element on a page and select "Inspect" to open DevTools with that element highlighted in the Elements panel. This shows you the exact HTML structure surrounding the data you want. Pay attention to class names and IDs. A price might be inside <span class="product-price">$29.99</span>. That class name, product-price, is the selector you will use in whatever extraction method you choose.

DevTools element inspection:
Right-click element → Inspect
→ Elements panel shows HTML structure
→ Note class names and tag hierarchy

The Elements panel also shows you whether the data exists in the initial HTML or is loaded dynamically. If you right-click the page, select "View Page Source," and search for the data text, you can confirm whether it is in the static HTML. If the data appears in DevTools but not in the page source, it was loaded by JavaScript, which means simple HTTP request tools will not find it.

Console Extraction

The Console tab in DevTools lets you run JavaScript directly on the page. This is incredibly useful for extracting structured data. For example, to extract all links from a page:

// Extract all links on the page
const links = [...document.querySelectorAll('a')];
const data = links.map(a => ({
  text: a.textContent.trim(),
  href: a.href
}));
console.table(data);

The console.table() function displays the results as a formatted table right in the console. You can then right-click the table and select "Copy table" to get a tab-separated version that pastes perfectly into a spreadsheet.

For more specific extractions, adjust the selector. To grab every product name and price from an e-commerce page, inspect one product to find the class names, then run something like:

// Extract product names and prices
const products = [...document.querySelectorAll('.product-card')];
const data = products.map(p => ({
  name: p.querySelector('.product-title')?.textContent.trim(),
  price: p.querySelector('.product-price')?.textContent.trim()
}));
console.table(data);

I use this console method more than any other scraping technique. It works on dynamic pages (because DevTools runs in the fully rendered browser context), handles any page structure, and outputs data in a format ready for spreadsheets. The only limitation is that it works one page at a time. For multi-page scraping, you need a different tool.

Network Tab for API Data

Many modern websites load their data from APIs using JavaScript fetch or XHR requests. The Network tab in DevTools records all of these requests. When you load a page that displays, say, a list of products, filter the Network tab to "Fetch/XHR" and look for JSON responses. Often, the API returns clean, structured JSON data that is far easier to work with than the HTML.

Once you find the API endpoint, you can call it directly. Copy the request URL, open it in a new browser tab, and you get the raw JSON. Some APIs require specific headers (like authentication tokens), which you can see in the Network tab's Headers section. For public APIs without authentication, you can use the URL directly in scripts or tools.

Tip. In the Network tab, right-click any XHR request and select "Copy as cURL" to get a ready-made command that reproduces the exact request with all headers and cookies. This is invaluable for replicating API calls outside the browser.

Google Sheets IMPORTHTML and IMPORTXML

Google Sheets has two built-in functions that turn your spreadsheet into a web scraper. They are free, require zero setup, and work directly in your browser. I consider these the best starting point for anyone who needs to extract tabular data regularly.

IMPORTHTML

The IMPORTHTML function pulls tables or lists directly from a web page into your spreadsheet. The syntax is straightforward:

=IMPORTHTML("https://example.com/data-page", "table", 1)

The three parameters are the URL of the page, the type of element to extract ("table" or "list"), and the index number indicating which table or list on the page (1 for the first, 2 for the second, and so on). The function fetches the page, finds the specified element, and populates your spreadsheet with its data.

For example, to pull a country population table from Wikipedia, you would enter:

=IMPORTHTML("https://en.wikipedia.org/wiki/List_of_countries_by_population_(United_Nations)", "table", 1)

The entire table appears in your spreadsheet within seconds. Headers, data rows, everything. The data updates automatically when you open the spreadsheet, so you always have the latest version. I use this function extensively for tracking pricing tables, comparison charts, and statistical data that updates regularly.

IMPORTXML

The IMPORTXML function is more powerful but slightly more complex. It uses XPath expressions (a query language for selecting nodes in XML/HTML documents) to target specific data on a page:

=IMPORTXML("https://example.com/products", "//h2[@class='product-title']")

This formula fetches the page and returns the text content of every <h2> element with the class "product-title." XPath is extremely flexible. Here are common patterns I use regularly:

// All links on a page
=IMPORTXML(url, "//a/@href")

// All images (src attributes)
=IMPORTXML(url, "//img/@src")

// Text inside a specific class
=IMPORTXML(url, "//div[@class='price']/text()")

// The third paragraph on the page
=IMPORTXML(url, "//p[3]")

The real power of IMPORTXML becomes apparent when you combine it with other Google Sheets functions. Use IMPORTXML to pull raw data, then REGEXEXTRACT to clean it, SPLIT to separate fields, and QUERY to filter and sort. You can build a complete data pipeline entirely within a spreadsheet.

Limitations and Workarounds

Both functions have limitations. Google imposes a quota on how many IMPORT calls a single spreadsheet can make (roughly 50 active IMPORT formulas per sheet). They only work on publicly accessible pages (no login-required content). They cannot handle JavaScript-rendered content since they fetch only the initial HTML. And some websites block Google's servers, causing the functions to return errors.

| Function | Best For | Limitation |

|---|---|---|

| IMPORTHTML | Tables and lists | Only works with HTML table and list elements |

| IMPORTXML | Any structured data via XPath | Requires understanding XPath syntax |

| IMPORTDATA | CSV and TSV files | Only works with plain text data files |

| IMPORTFEED | RSS and Atom feeds | Limited to feed-format data sources |

When IMPORTHTML or IMPORTXML returns an error, try these steps in order. First, verify the URL is publicly accessible by opening it in an incognito browser window. Second, check if the page uses JavaScript to load its content (view source and search for the data). Third, try a different index number, as the table you want might not be the first one on the page. Fourth, add a cache-busting parameter to the URL (append ?t=1) to force a fresh fetch.

Free Online Scraping Tools

When copy-paste is too tedious and Google Sheets formulas cannot reach the data, several free online tools fill the gap. These tools provide visual interfaces for selecting data on web pages and exporting it in structured formats.

ParseHub

ParseHub is a desktop application (available for Windows, Mac, and Linux) that lets you scrape websites by clicking on the data you want. You open a page within ParseHub's built-in browser, click on a product name, and ParseHub recognizes the pattern and selects all similar elements. You then click on the price, and it adds that field to your extraction template. The free plan allows up to 200 pages per run and 5 projects.

What makes ParseHub stand out is its ability to handle JavaScript-rendered content. Because it runs a full browser engine, it can scrape single-page applications, infinite scroll pages, and content loaded via AJAX requests. It also handles pagination automatically. You click the "Next" button once, and ParseHub follows that pattern across all subsequent pages.

Octoparse

Octoparse is similar to ParseHub in concept but offers a cloud-based option in addition to its desktop client. The visual workflow builder lets you define extraction steps like "open URL," "click element," "scroll down," "extract data," and "go to next page." The free plan provides 10,000 records per export and limited cloud runs.

I find Octoparse particularly useful for scraping sites with complex navigation patterns. If you need to click through category menus, expand dropdown filters, or interact with search forms before the data appears, Octoparse's workflow approach handles these steps better than simpler tools.

Web Scraper (webscraper.io)

Web Scraper is a Chrome extension with a free tier that creates "sitemaps" (scraping blueprints) within Chrome Developer Tools. You define selectors visually by clicking elements on the page, then run the scraper to collect data across multiple pages. The results export as CSV. The Chrome extension version is free with no row limits, though it runs locally in your browser, which means your computer needs to stay on while it scrapes.

Instant Data Scraper

For the quickest possible extraction, Instant Data Scraper is a Chrome extension that uses AI to automatically detect tabular data on any page. Install it, navigate to a page with data, click the extension icon, and it presents its best guess at the data table. You can adjust the detection if needed, then export to CSV or Excel with one click. I reach for this tool when I need data from a single page and do not want to configure anything.

When You Need to Write Code

Everything I have covered so far handles the majority of scraping needs. But there are scenarios where code becomes necessary. If you need to scrape thousands of pages on a schedule, interact with complex authentication flows, or process data through custom logic before saving it, a script is the right tool.

Python is the dominant language for web scraping, and for good reason. Two libraries handle most use cases: requests for fetching pages and BeautifulSoup for parsing HTML.

Python Requests and BeautifulSoup

Here is a minimal scraping script that extracts all article headlines from a blog page:

import requests
from bs4 import BeautifulSoup

url = "https://example.com/blog"
response = requests.get(url)
soup = BeautifulSoup(response.text, "html.parser")

headlines = soup.select("h2.post-title")
for h in headlines:
    print(h.get_text(strip=True))

The requests.get() function fetches the page HTML. BeautifulSoup parses it into a navigable tree. The .select() method accepts CSS selectors (the same kind you identified using Chrome Developer Tools). And .get_text() extracts the visible text content.

To save results to a CSV file, add Python's built-in csv module:

import csv
import requests
from bs4 import BeautifulSoup

url = "https://example.com/products"
response = requests.get(url)
soup = BeautifulSoup(response.text, "html.parser")

products = soup.select(".product-card")

with open("products.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["Name", "Price", "Rating"])
    for p in products:
        name = p.select_one(".title").get_text(strip=True)
        price = p.select_one(".price").get_text(strip=True)
        rating = p.select_one(".rating").get_text(strip=True)
        writer.writerow([name, price, rating])

Handling JavaScript-Rendered Pages

The requests library only fetches raw HTML. It does not execute JavaScript. For pages that render content dynamically, you need a browser automation tool. Selenium and Playwright are the two main options.

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://example.com/dynamic-page")
    page.wait_for_selector(".product-card")

    products = page.query_selector_all(".product-card")
    for product in products:
        name = product.query_selector(".title").inner_text()
        print(name)

    browser.close()

Playwright launches a real browser (headless, meaning no visible window), navigates to the page, waits for JavaScript to render the content, then lets you query elements just like you would in DevTools. It is slower than requests because it runs an entire browser, but it handles any page that a human browser can render.

Respecting Servers When Scripting

When writing scraping scripts, always add delays between requests. Hitting a server with hundreds of rapid requests can degrade the site's performance for real users and may get your IP address blocked. I typically add a 1 to 3 second delay between requests using Python's time.sleep():

import time
import random

for url in urls:
    response = requests.get(url)
    # process response...
    time.sleep(random.uniform(1, 3))

The random delay between 1 and 3 seconds mimics natural browsing patterns and is usually sufficient to avoid rate limiting. For larger scraping jobs, I also set a custom User-Agent header identifying my script, check robots.txt programmatically, and implement exponential backoff when I receive 429 (Too Many Requests) responses.

Common Scraping Mistakes

After years of extracting data from websites, I have made every mistake on this list at least once. Learning from mine will save you time and frustration.

Not Checking the Page Source First

The single most common mistake I see is jumping into a scraping tool without first understanding the page structure. Five minutes with Chrome DevTools tells you whether the data is in static HTML or loaded dynamically, what selectors to use, whether an API endpoint exists that returns the data as JSON, and whether the site uses anti-scraping measures. Skipping this reconnaissance step leads to choosing the wrong tool and wasting time debugging extraction that was never going to work.

Ignoring Available APIs

Many websites that display data on their pages also offer APIs that return the same data in structured JSON format. These APIs are often documented and intended for external use. Scraping HTML when a clean API exists is like taking a photograph of a document instead of downloading the PDF. Always check for an API first. Look in the Network tab of DevTools, check the website's developer documentation, and search for "[site name] API" before building a scraper.

Scraping Too Aggressively

Sending hundreds of requests per second to a website will get your IP blocked, may degrade the site for other users, and could create legal liability. I have seen beginners run scraping scripts with no delays and wonder why they get blocked after 50 requests. Every responsible scraping script includes rate limiting. A request every 1 to 3 seconds is reasonable for most sites. If you need thousands of pages, schedule the scraping over hours or days rather than trying to finish in minutes.

Not Handling Errors Gracefully

Websites go down. Pages change structure. Network connections drop. A scraping process that does not handle errors will crash partway through, potentially losing all collected data. Always save results incrementally (write to CSV after each page, not at the end), implement retry logic for failed requests, and wrap extraction code in try/except blocks that log errors without stopping the entire process.

Hardcoding Selectors Without Monitoring

Website HTML structures change. A class name that works today might be renamed next month when the site deploys an update. If your scraping runs on a schedule, include validation that checks whether the expected elements exist and alerts you when they do not. A simple check like "did this page return at least 10 products?" catches most structural changes before they silently corrupt your data.

Scraping Personal Data Without a Legal Basis

I mentioned this in the legal section, but it bears repeating because of how frequently I see it violated. Scraping names, emails, phone numbers, and other personal data from public directories or social media profiles may be technically possible, but it carries significant legal risk under GDPR, CCPA, and similar regulations. If your scraping project involves personal data, get legal advice before starting.

| Mistake | Consequence | Prevention |

|---|---|---|

| Not checking page source | Choosing wrong tool, wasted time | Spend 5 minutes in DevTools first |

| Ignoring available APIs | Brittle HTML scraping when clean JSON exists | Check Network tab and site documentation |

| No rate limiting | IP blocks, legal risk, server impact | Add 1-3 second delays between requests |

| No error handling | Data loss on crashes | Save incrementally, implement retries |

| Hardcoded selectors | Silent data corruption when site changes | Add validation checks to scheduled scrapes |

| Scraping personal data carelessly | GDPR/CCPA violations, legal action | Consult legal counsel for PII scraping |

Choosing the Right Method for the Job

The biggest meta-mistake is overcomplicating the extraction. I have watched developers write 200-line Python scripts to scrape data that they could have grabbed with a Google Sheets IMPORTHTML formula in 10 seconds. Match the tool to the task:

  • Single table on one page: copy-paste or IMPORTHTML
  • Specific data fields from one page: Chrome DevTools console
  • Recurring data from a public page: Google Sheets IMPORTXML with auto-refresh
  • Multiple pages, visual selection: Web Scraper Lite or Instant Data Scraper
  • Complex multi-step navigation: ParseHub or Octoparse
  • Thousands of pages, custom processing: Python with requests/BeautifulSoup
  • Dynamic JavaScript-heavy sites at scale: Python with Playwright or Selenium

Start with the simplest method that might work. If it does not, move one step up in complexity. More often than not, you never need to reach for code.
