Wikipedia: Password Strength

Password strength is a measure of the effectiveness of a password against guessing or brute-force attacks. In its usual form, it estimates how many trials an attacker who does not have direct access to the password would need, on average, to guess it correctly. The strength of a password is a function of length, complexity, and unpredictability. Using strong passwords lowers overall risk of a security breach, but strong passwords do not replace the need for other effective security controls.

How Passwords Get Cracked

Understanding how attackers break passwords is the first step toward creating ones they cannot. There are five primary attack methods, and each exploits different weaknesses.

Brute Force

A brute-force attack tries every possible combination of characters until it finds the right one. The time required depends on password length, character set size, and the attacker's hardware speed. Modern GPUs (like the NVIDIA RTX 5090) can compute over 150 billion MD5 hashes per second. Against properly hashed passwords (bcrypt with a cost factor of 12), that same GPU is limited to roughly 100 hashes per second, which is why hash algorithm choice matters enormously.

Dictionary Attacks

Dictionary attacks try common words, phrases, and known passwords from previous breaches. Attackers maintain wordlists containing millions of entries, including common substitutions (p@ssw0rd, l3tme1n). These attacks are fast because they skip uncommon combinations and focus on what people actually use. The RockYou breach list alone contains 14 million unique passwords and remains a staple of every attacker's toolkit.

Credential Stuffing

When a service gets breached and its user database leaks, attackers try those username/password pairs on other services. Because roughly 65% of people reuse passwords across multiple accounts, credential stuffing has a high success rate. It requires no cracking at all if the breached service stored passwords in plaintext or used weak hashing.

Rainbow Tables

Rainbow tables are precomputed lookup tables that map hash values back to their original passwords. If a database stores unsalted hashes, an attacker can look up any hash and find the password in seconds. Modern password hashing algorithms (bcrypt, scrypt, Argon2) include a random salt with each hash, making rainbow tables useless because each password has a unique salt.

Social Engineering and Phishing

The most effective password attacks often bypass technical defenses entirely. Phishing emails that mimic legitimate login pages, phone calls from fake support agents, and shoulder surfing all target human behavior rather than cryptographic weaknesses. Two-factor authentication is the strongest defense against phishing because even a stolen password is not sufficient to log in.

What Makes a Password Strong

Password strength comes down to entropy: the number of possible combinations an attacker must try. Entropy is measured in bits. A password with 80 bits of entropy has 2^80 possible values. Every additional bit doubles the search space.

Passphrases vs. Random Strings

A passphrase is a sequence of random words, like "correct horse battery staple" (the well-known XKCD example). Passphrases are easier to memorize than random character strings and can achieve high entropy through length. A 6-word passphrase from a 7,776-word dictionary (Diceware) has about 78 bits of entropy, which is strong enough for nearly any purpose.

Random character strings generated by a password manager are denser in entropy per character but impossible to memorize. Use passphrases for the few passwords you must remember (master password, device login) and random strings for everything else.

Password Managers: Why and How

The average person has over 100 online accounts. Remembering a unique, strong password for each one is not humanly possible. Password managers solve this by generating, storing, and auto-filling credentials. You remember one master password; the manager handles the rest.

How Password Managers Work

A password manager encrypts your credential vault using your master password as the key. The encryption typically uses AES-256 or XChaCha20, both of which are considered unbreakable with current technology. The manager derives an encryption key from your master password using a key derivation function (PBKDF2, Argon2, or scrypt) with hundreds of thousands of iterations, making brute-force attacks against the vault impractical.

Zero-knowledge architecture means the password manager company never has access to your decrypted vault. If they get breached (as happened to LastPass in 2022), attackers get encrypted blobs that are only as vulnerable as your master password is weak.

How Password Hashing Works

When you create an account on a properly built service, the service does not store your password. It stores a hash of your password. A hash function takes input of any length and produces a fixed-length output that is computationally infeasible to reverse.

Hash Functions Used for Passwords

Not all hash functions are suitable for passwords. General-purpose hashes like MD5 and SHA-256 are designed to be fast, which is the opposite of what you want for password storage. Password-specific hash functions are deliberately slow.

The speed difference is critical. At 6 nanoseconds per hash, an attacker can try 150 billion MD5 guesses per second on a single GPU. At 250 milliseconds per hash, bcrypt limits the same attacker to roughly 100 guesses per second. That means a password that falls to MD5 in 3 seconds would take bcrypt over 140 years.

Salting Explained

A salt is a random string added to the password before hashing. Each user gets a unique salt, stored alongside the hash. Without salts, two users with the same password would have the same hash, allowing attackers to crack once and compromise all matching accounts. With salts, each hash is unique even for identical passwords. bcrypt, scrypt, and Argon2 include automatic salting.

Two-Factor Authentication (2FA)

Two-factor authentication adds a second verification step after your password. Even if an attacker has your password, they cannot log in without the second factor. 2FA reduces account compromise risk by over 99% according to Google's internal data.

Types of 2FA, Ranked by Security

  1. Hardware security keys (YubiKey, Google Titan Key): Physical USB or NFC devices that use FIDO2 cryptographic protocols. Immune to phishing because the key verifies the requesting domain. Recommended for high-value accounts.
  2. Authenticator apps (Authy, Google Authenticator, Microsoft Authenticator): Generate time-based one-time passwords (TOTP) that change every 30 seconds. Resistant to phishing but not immune (an attacker with a real-time phishing proxy can relay codes). Store backup codes securely.
  3. Push notifications (Duo, Microsoft Authenticator push): Send a yes/no prompt to your phone. Convenient but vulnerable to "MFA fatigue" attacks where attackers spam prompts until the user accidentally approves.
  4. SMS codes: Sent to your phone number via text message. Vulnerable to SIM swapping (an attacker convinces your carrier to transfer your number), SS7 interception, and message forwarding. Still better than no 2FA but the weakest option.

Enable 2FA on every account that supports it, starting with email (the account that controls password resets for everything else), financial accounts, and cloud storage.

Passkeys: The Future of Authentication

Passkeys represent the most significant shift in authentication since the password was invented. Based on the FIDO2/WebAuthn standard, passkeys replace the shared-secret model (where both you and the server know the password) with public-key cryptography (where the server knows only a public key and authentication happens with a private key that never leaves your device).

How Passkeys Work

When you register a passkey for a site, your device generates a key pair. The private key stays on your device (protected by biometrics or PIN). The public key goes to the server. To log in, the server sends a challenge; your device signs it with the private key after biometric verification. The server verifies the signature with the public key. Your secret never crosses the network.

Why Passkeys Are More Secure

  • No phishing risk: Passkeys are bound to the domain. A fake site cannot request your passkey for the real site.
  • No reuse risk: Each passkey is unique to each site.
  • No database breach risk: Servers store only public keys, which are useless to attackers.
  • No memorization required: Biometrics or device PIN handles authentication.

Current Passkey Support (March 2026)

Apple, Google, and Microsoft all support passkeys natively. Major services including Google, Apple, Microsoft, Amazon, PayPal, GitHub, and Coinbase support passkey login. Adoption is accelerating, but most services still offer passkeys as an alternative to passwords rather than a replacement. Full password deprecation is likely years away due to the long tail of legacy systems and edge cases.

Common Password Mistakes to Avoid

Security breaches consistently reveal the same patterns. Here are the most common password mistakes, all of which are easily avoidable.

Using personal information: Pet names, birthdays, street addresses, and phone numbers are trivially discoverable through social media, public records, and data broker sites. Never use personally identifiable information in a password.

Common substitutions: Replacing "a" with "@", "e" with "3", or "o" with "0" does not meaningfully increase security. Attackers test these substitutions automatically. "p@ssw0rd" is in every dictionary wordlist.

Keyboard patterns: "qwerty", "123456", "zxcvbn", and similar patterns are among the first combinations tested. They provide near-zero entropy despite looking random to the user.

Short passwords with high complexity: An 8-character password with uppercase, lowercase, numbers, and symbols has about 52 bits of entropy. A 16-character lowercase-only password has about 75 bits. Length beats complexity.

Reusing passwords across sites: If any one of those sites gets breached, every account sharing that password is compromised. This is the single most impactful mistake because it turns one breach into many.

Writing passwords on sticky notes: Physical security matters. A note on your monitor is visible to anyone who walks past your desk, including cleaning staff, visitors, and anyone who photographs your workspace.

Building a Personal Security Practice

Step 1: Set Up a Password Manager

Install Bitwarden (or your preferred manager) on all your devices. Create a strong master password using a 5-6 word passphrase. Enable 2FA on the password manager account itself. Write down the master password and recovery code, store them in a secure physical location (not on your computer), and never share them.

Step 2: Audit and Replace Existing Passwords

Export passwords from your browser and import them into the password manager. Review each entry. Replace any password that is: shorter than 12 characters, used on more than one site, based on personal information, or found in the Have I Been Pwned breach database (haveibeenpwned.com/Passwords). Generate new random passwords through the manager.

Step 3: Enable 2FA Everywhere

Start with email, then financial accounts, then social media and cloud storage. Use an authenticator app as the default. Upgrade to a hardware key for your most critical accounts. Store 2FA backup codes in your password manager (it is more secure than printing them, and if your password manager is compromised, the attacker has your passwords anyway).

Step 4: Monitor for Breaches

Sign up for breach notifications at haveibeenpwned.com. Enable notifications in your password manager for compromised credentials (Bitwarden has a built-in breach report). When notified, change the affected password immediately and check for unauthorized account activity.

Step 5: Adopt Passkeys Where Available

For services that support passkeys (Google, Apple, Microsoft, GitHub, PayPal, and others), register a passkey as your primary login method. Keep your password active as a backup for now, but prioritize passkey login. As passkey support expands, your reliance on passwords will naturally decrease.

Frequently Asked Questions

Is it safe to use the same password for accounts I do not care about? No. A compromised "throwaway" account can be used to gather personal information, serve as a pivot point for social engineering, or provide an attacker with a username/email combination to test elsewhere. Use your password manager to generate unique passwords for everything, regardless of perceived importance.

How do I remember my master password? Use a passphrase of 5 to 6 random words. Practice typing it several times per day for the first week. Some people find it helpful to create a mental story linking the words. Never write it on your computer; if you must write it, store the physical copy in a secure location like a safe or safety deposit box.

Are password strength meters accurate? Most website-embedded password meters are simplistic and unreliable. They often rate "P@ssword1" as "strong" because it meets complexity checkboxes despite being in every dictionary list. The zxcvbn library (developed by Dropbox) is one of the more accurate strength estimators because it accounts for common patterns, dictionary words, and keyboard sequences.

What happens if I lose access to my 2FA device? This is why backup codes exist. When you set up 2FA, the service provides one-time-use backup codes. Store these in your password manager. If you lose your 2FA device, use a backup code to log in and set up a new device. For hardware keys, register two keys per account and keep one as a backup.

Can quantum computers break my passwords? Quantum computing threatens asymmetric encryption (RSA, ECC) used in passkeys and TLS, but its impact on password hashing is more limited. Grover's algorithm provides a quadratic speedup against symmetric ciphers and hashes, effectively halving the bit strength. A 128-bit-entropy password would have 64 bits of quantum security, which is still substantial. Practical quantum computers capable of this are not expected before the 2030s at the earliest.

What is credential stuffing and how do I protect against it? Credential stuffing is when attackers take username/password combinations leaked from one breached service and try them on other services. The only effective defense is to never reuse passwords. A password manager makes this practical. If you hear about a breach at a service you use, change that password immediately, even if the company says passwords were hashed.
