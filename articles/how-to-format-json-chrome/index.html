Why JSON Readability Matters

In my experience building 20+ Chrome extensions and working with APIs daily, I spend a significant portion of every working day staring at JSON. API responses, configuration files, database exports, webhook payloads, logging output. JSON has become the default data interchange format across the web, and for good reason. It is human-readable in theory. In practice, a 400-line JSON response crammed onto a single line with no whitespace is about as readable as a wall of hexadecimal.

The problem is not with JSON itself. The specification is clean and minimal. The problem is that most systems strip whitespace before transmitting JSON to save bandwidth. A 50KB API response might shrink to 38KB after removing indentation and line breaks. That savings matters at scale, but it means the JSON that arrives in your browser is almost always minified.

When I am debugging an API integration, the difference between reading minified JSON and properly formatted JSON is the difference between spending thirty seconds finding the problematic field and spending five minutes scrolling sideways through a single line. Multiply that across dozens of API calls per debugging session and the time adds up fast.

Readability also matters for validation. When JSON is properly indented, structural issues become visually obvious. A missing closing bracket stands out. A misplaced comma catches your eye. When the same JSON is on one line, those errors hide in the middle of thousands of characters.

Beyond debugging, formatted JSON is essential for documentation. When I include API response examples in technical documentation, those examples need to be readable. Team members need to understand the data structure at a glance, not parse it character by character.

The good news is that Chrome provides several built-in ways to format JSON, and extensions fill the gaps where native tools fall short. I will walk through every method I use, starting with the tools already built into Chrome and moving to specialized options for more demanding workflows.

Definition: According to Wikipedia, JSON (JavaScript Object Notation) is an open standard file format and data interchange format that uses human-readable text to store and transmit data objects consisting of attribute-value pairs and arrays. It is a language-independent format derived from JavaScript and defined by RFC 8259.

Chrome DevTools Network Tab JSON Viewer

The fastest way to view formatted JSON in Chrome is through DevTools, and most developers already have it open while working. The Network tab provides a built-in JSON viewer that handles the formatting automatically.

Viewing API Responses

Open DevTools by pressing F12 or Ctrl+Shift+I on Windows and Linux, or Cmd+Option+I on macOS. Navigate to the Network tab. If no requests are showing, reload the page while keeping DevTools open. The Network tab only records traffic that occurs while it is active.

Click on any request that returns JSON. You will typically find these by filtering for "Fetch/XHR" using the filter buttons at the top of the Network panel. When you click a request, a detail panel opens with several sub-tabs.

The Preview sub-tab is where the magic happens. Chrome automatically parses the JSON response and displays it as an expandable tree. Each object can be collapsed or expanded by clicking the arrow next to it. Arrays show their length in brackets. Strings, numbers, booleans, and null values are color-coded for quick scanning.

The Response sub-tab shows the raw response body. For JSON, this is typically the minified version that came over the wire. The Preview tab is almost always what you want when debugging.

Copying Formatted JSON from DevTools

Right-click on any node in the Preview tree and select "Copy value" to copy that specific subtree as JSON. For the entire response, right-click the root node. Chrome copies the JSON with proper indentation, ready to paste into your editor or documentation.

You can also right-click in the Preview pane and select "Store as global variable." DevTools creates a temporary variable (usually temp1, temp2, and so on) in the Console that holds the parsed JSON object. From there, you can manipulate it with JavaScript, filter specific fields, or re-format it however you need.

Tip. If the Preview tab shows "Failed to load response data," the response may have been too large or the request may have been cancelled before completion. Try reproducing the request and ensure the full response loads before inspecting it.

Filtering Requests by Content Type

When a page makes dozens of requests, finding the JSON response you care about requires filtering. Beyond the type buttons at the top, you can type directly in the filter box. Enter method:POST to see only POST requests, or status-code:200 to filter by status. For JSON specifically, try mime-type:application/json to show only responses served with the JSON content type.

The search also supports negative filters. Enter -domain:cdn.example.com to exclude requests to a specific domain. Combining filters narrows results quickly when you are working with a page that generates heavy network traffic.

Console Tricks for Pretty Printing JSON

The Chrome Console is more powerful than most developers realize when it comes to working with JSON. Beyond simply logging objects, there are several techniques I use daily that turn the Console into a capable JSON formatting tool.

JSON.stringify with Indentation

The JSON.stringify() method accepts three arguments. The first is the value to convert. The second is a replacer function or array (usually null when you want everything). The third is the indentation level. This third argument is the key to pretty printing.

// Pretty print with 2-space indentation
JSON.stringify(data, null, 2)

// Pretty print with 4-space indentation
JSON.stringify(data, null, 4)

// Pretty print with tab indentation
JSON.stringify(data, null, '\t')

The indentation argument accepts either a number (spaces per level) or a string (used as the indentation character). I prefer 2 spaces for most work because it keeps deeply nested structures from scrolling off the right edge of the screen.

To use this on an API response, first store the response in a variable. If you have already captured it in the Network tab, right-click and select "Store as global variable." Then run the stringify command in the Console.

// After storing a network response as temp1
console.log(JSON.stringify(temp1, null, 2))

Using console.table for Tabular Data

When your JSON contains an array of objects with consistent keys, console.table() renders it as an interactive HTML table directly in the Console. This is significantly easier to read than an expanded tree when you are comparing values across multiple records.

// Display array of objects as a sortable table
console.table(data.users)

// Show only specific columns
console.table(data.users, ['name', 'email', 'role'])

The second argument to console.table() lets you specify which columns to display. This is useful when objects have many properties and you only care about a few. The resulting table is sortable by clicking column headers.

Parsing and Re-formatting a JSON String

Sometimes you receive JSON as a raw string, perhaps copied from a log file, a database record, or an error message. You can parse and re-format it in one step.

// Parse a raw JSON string and pretty print it
console.log(JSON.stringify(JSON.parse(rawString), null, 2))

If the string contains escape characters (common when JSON is embedded inside another JSON string), you may need to parse it twice.

// Double-encoded JSON (string within a string)
let inner = JSON.parse(outerObject.jsonField)
console.log(JSON.stringify(inner, null, 2))

Filtering with the Replacer Function

The second argument to JSON.stringify() is a replacer, and it is far more useful than most people realize. You can pass an array of property names to include only specific fields.

// Only include specific properties
JSON.stringify(data, ['id', 'name', 'status'], 2)

Or pass a function that controls which values are included. Returning undefined from the replacer omits that property entirely.

// Remove all null values from the output
JSON.stringify(data, (key, value) => value === null ? undefined : value, 2)

// Redact sensitive fields
JSON.stringify(data, (key, value) => {
  if (['password', 'token', 'secret'].includes(key)) return '[REDACTED]'
  return value
}, 2)

I use the redaction pattern frequently when sharing API responses with team members. It formats the JSON nicely while automatically stripping sensitive fields.

Tip. You can save frequently-used JSON formatting snippets in the Sources panel under Snippets. They persist across browser sessions and can be run on any page with a keyboard shortcut.

Browser URL Bar Trick and Chrome's Built-in Viewer

Starting with Chrome 114, the browser includes a built-in JSON viewer that activates when you navigate directly to a URL that returns a JSON response. This works for any API endpoint you can access without authentication, and it is one of the least-known features among developers I talk to.

How the Built-in Viewer Works

Type or paste an API URL directly into Chrome's address bar. If the server responds with a Content-Type: application/json header, Chrome renders the JSON with syntax highlighting, collapsible nodes, and proper indentation. No extension required. No DevTools required.

For example, navigating to a public REST API endpoint like https://api.github.com/users/octocat displays the response as formatted, color-coded JSON with expandable objects and arrays. The viewer handles nested structures of any depth and maintains performance even with moderately large responses.

When the Built-in Viewer Activates

The viewer only activates when two conditions are met. First, the URL must be loaded as a top-level navigation (typed into the address bar or accessed via a direct link). It does not activate for JSON loaded in iframes or via JavaScript. Second, the response must include a JSON-compatible Content-Type header, specifically application/json or similar variants like application/vnd.api+json.

If the server sends JSON with a text/plain or text/html Content-Type, Chrome's viewer does not activate. The response appears as raw, unformatted text. This is a common issue with misconfigured servers and one of the main reasons people still need JSON formatter extensions.

Limitations of the Built-in Viewer

Chrome's native JSON viewer is useful for quick inspections, but it lacks several features that daily JSON work demands. There is no search feature within the formatted output. You cannot collapse or expand all nodes at once. There is no way to copy a specific subtree cleanly. There is no path display showing where you are in the structure. And there is no way to switch between tree view and raw view without viewing the page source.

For authenticated API endpoints, the built-in viewer does not help because you cannot easily attach authorization headers to a navigation request from the address bar. Those requests go through the browser's default cookie-based authentication only.

Using the Data URL Trick

For JSON strings you have on your clipboard that are not from a URL, you can use a data URI to trigger Chrome's JSON viewer. Paste the following into the address bar, replacing the JSON with your own data.

data:application/json,{"name":"example","values":[1,2,3]}

Chrome renders this as formatted JSON using the built-in viewer. This trick is useful when you have a JSON string from a log, email, or chat message and want to view it formatted without opening DevTools or an external tool. Note that very long JSON strings may exceed the URL length limit and will not work with this method.

Validating JSON and Common Syntax Errors

Formatting JSON is only half the battle. If the JSON is malformed, no formatter can fix it automatically. Understanding the common syntax errors in JSON and how to diagnose them efficiently will save you more debugging time than any tool.

The JSON Specification in Brief

JSON allows six value types: strings (double-quoted), numbers, booleans (true and false), null, objects (curly braces with key-value pairs), and arrays (square brackets with ordered values). That is it. No comments. No trailing commas. No single quotes. No undefined. The specification is RFC 8259 and it is intentionally minimal.

Common Syntax Errors

After years of debugging JSON issues, I have found that the same handful of errors account for the vast majority of problems.

Trailing commas are the most frequent offender. JavaScript objects allow trailing commas, so developers write JSON with the same habit. JSON does not permit a comma after the last element in an object or array.

// Invalid - trailing comma after "active"
{
  "name": "example",
  "active": true,
}

// Valid
{
  "name": "example",
  "active": true
}

Single quotes instead of double quotes come next. JavaScript allows both, but JSON requires double quotes for all strings and property names.

// Invalid - single quotes
{'name': 'example'}

// Valid - double quotes
{"name": "example"}

Unquoted property names are another common problem, especially when JSON is hand-written rather than generated by a serializer.

// Invalid - unquoted key
{name: "example"}

// Valid - quoted key
{"name": "example"}

Comments in JSON are not allowed. Neither single-line (//) nor multi-line (/* */) comments are part of the specification. If you need JSON with comments, you are looking for JSON5 or JSONC, which are supersets used by tools like VS Code for configuration files. Standard JSON parsers reject comments.

Special number values like NaN, Infinity, and -Infinity are not valid JSON. These exist in JavaScript but have no JSON representation. If you need to represent these values, you must use a string or null as a fallback.

Validating JSON in the Chrome Console

The simplest validation method is to use JSON.parse() in the Console. Wrap your JSON string in the parse call and Chrome either returns the parsed object (valid) or throws an error with a position indicator (invalid).

// Validate a JSON string
JSON.parse('{"name": "test", "value": 42}')
// Returns: {name: "test", value: 42}

// Invalid JSON shows the error position
JSON.parse('{"name": "test", "value": 42,}')
// SyntaxError: Unexpected token } in JSON at position 33

The position number in the error message tells you exactly which character caused the failure. Count from the beginning of the string to find it. In the example above, position 33 is the closing brace that immediately follows the trailing comma.

Multi-step Validation for Complex Issues

When the error position does not immediately reveal the problem, I use a binary search approach. I paste the first half of the JSON and try to parse it (adding whatever closing brackets are needed). If it parses, the error is in the second half. If it does not, the error is in the first half. I repeat until I find the problematic section. This works well for large JSON files where scrolling to character position 14,387 is not practical.

This is a pragmatic workaround, not a specification-compliant approach, so use it only when you control the pipeline.

Working with Large JSON Files

API responses in production environments frequently exceed what casual tools handle comfortably. I have worked with JSON exports from analytics platforms that run to 50 MB or more. At that scale, browser-based tools start to struggle, and you need different strategies.

Why Large JSON is Problematic in Browsers

Every DOM element costs memory. A tree view of a 10 MB JSON file might generate tens of thousands of DOM nodes, each consuming a few hundred bytes of memory plus layout and rendering overhead. A 50 MB JSON file could require a gigabyte or more of memory just for the DOM tree, on top of the memory for the parsed JavaScript object. Chrome tabs have memory limits, and large JSON files hit those limits fast.

The parsing step itself is also expensive. JSON.parse() is highly optimized in V8, but it still needs to allocate memory for every string, number, array, and object in the structure. For a 50 MB file with millions of values, parsing alone can take several seconds.

Streaming with the Console

When I need to work with large JSON in the browser, I avoid rendering the entire tree. Instead, I use the Console to navigate specific paths. After loading the JSON into a variable (either via fetch or by storing a Network response), I access only the parts I need.

// Fetch large JSON and explore specific paths
let response = await fetch('/api/large-export')
let data = await response.json()

// Check the top-level structure without expanding everything
Object.keys(data)

// Look at array lengths before diving in
data.records.length

// Inspect a single record
data.records[0]

// Find specific records with filter
data.records.filter(r => r.status === 'error').length

This approach uses minimal memory because you are only displaying small slices of the data at a time. The full object lives in V8's heap, which is efficient, rather than being duplicated into DOM nodes.

Using the Command Line with jq

For JSON files above 20 MB, I move to the command line. The jq tool is a lightweight and flexible command-line JSON processor that handles files of any size efficiently. It reads JSON from stdin or a file, applies transformations, and outputs the result.

# Pretty print a JSON file
jq '.' large-file.json

# Extract specific fields
jq '.records[] | {id, name, status}' large-file.json

# Count records matching a condition
jq '[.records[] | select(.status == "error")] | length' large-file.json

# Get the first 5 records, formatted
jq '.records[:5]' large-file.json

jq processes JSON in a streaming fashion for many operations, meaning it does not need to hold the entire parsed structure in memory. For truly massive files (hundreds of megabytes), use jq with the --stream flag for event-based processing.

Splitting Large Files

When I need to view a large JSON file in a browser-based tool, I split it first. If the top-level structure is an array, I extract a subset.

# Extract records 0-99 to a smaller file
jq '.records[0:100]' large-file.json > subset.json

# Or extract just the schema (first record)
jq '.records[0]' large-file.json > sample-record.json

The subset file loads quickly in any browser tool and gives me the structural understanding I need. Once I know the shape of the data, I use targeted jq queries or Console commands to work with the full file.

Memory Management in Chrome

If you do load a large JSON file in Chrome, keep an eye on memory usage. Open Chrome's built-in Task Manager (Shift+Esc on Windows/Linux, or Window menu on macOS) to see per-tab memory consumption. If a tab's memory usage climbs past 1 GB, consider closing it and working with a smaller subset instead. Chrome will eventually kill the tab anyway if it exceeds the memory limit.

When using DevTools, the Memory panel can profile heap snapshots to show exactly what is consuming memory. This is useful for understanding whether the memory is going to the parsed JSON object, the DOM tree, or extension overhead.

JSON to CSV, YAML, and Other Format Conversions

JSON is the dominant data format for APIs, but it is not always the right format for the next step in your workflow. Spreadsheet users need CSV. Configuration management tools prefer YAML. Some systems expect XML. Converting between these formats is a regular task, and Chrome provides several ways to handle it.

JSON to CSV in the Console

For flat arrays of objects (the most common structure in API responses), converting to CSV in the Console is straightforward. The technique extracts headers from the first object and maps each record to a comma-separated row.

// Convert an array of objects to CSV
function jsonToCsv(data) {
  const headers = Object.keys(data[0])
  const rows = data.map(obj =>
    headers.map(h => {
      let val = obj[h]
      if (typeof val === 'string' && (val.includes(',') || val.includes('"')))
        val = '"' + val.replace(/"/g, '""') + '"'
      return val
    }).join(',')
  )
  return [headers.join(','), ...rows].join('\n')
}

// Usage
let csv = jsonToCsv(data.users)
console.log(csv)

// Copy to clipboard
copy(jsonToCsv(data.users))

The copy() function is a Console-only command that copies any value to the clipboard. Combined with the CSV conversion function, you can go from a JSON API response to a clipboard-ready CSV in seconds, ready to paste into a spreadsheet.

JSON to YAML

YAML conversion is more complex because YAML has features (references, multiline strings, comments) that JSON does not. For basic conversions, a simple recursive function handles the common cases.

// Basic JSON to YAML conversion
function jsonToYaml(obj, indent = 0) {
  const pad = ' '.repeat(indent)
  if (Array.isArray(obj)) {
    return obj.map(item =>
      pad + '- ' + (typeof item === 'object'
        ? '\n' + jsonToYaml(item, indent + 2)
        : item)
    ).join('\n')
  }
  return Object.entries(obj).map(([key, val]) => {
    if (val === null) return pad + key + ': null'
    if (typeof val === 'object')
      return pad + key + ':\n' + jsonToYaml(val, indent + 2)
    if (typeof val === 'string')
      return pad + key + ': "' + val + '"'
    return pad + key + ': ' + val
  }).join('\n')
}

console.log(jsonToYaml(data))

For production use, I recommend a proper library like js-yaml rather than a Console snippet. But for quick one-off conversions during debugging, the snippet above covers the common cases.

JSON to XML

JSON-to-XML conversion requires more decisions because XML has features (attributes versus elements, namespaces, CDATA sections) that do not map cleanly from JSON. A basic conversion treats every property as an element.

// Basic JSON to XML conversion
function jsonToXml(obj, rootName = 'root') {
  function convert(data, name) {
    if (data === null) return '<' + name + '/>'
    if (typeof data !== 'object') return '<' + name + '>' + data + '</' + name + '>'
    if (Array.isArray(data))
      return data.map(item => convert(item, name)).join('\n')
    let children = Object.entries(data)
      .map(([k, v]) => convert(v, k)).join('\n')
    return '<' + name + '>\n' + children + '\n</' + name + '>'
  }
  return '<?xml version="1.0"?>\n' + convert(obj, rootName)
}
