JSON Is Everywhere in the Browser

Before getting into specific tools, it helps to understand just how many places JSON shows up inside Chrome. Most developers think of API responses when they hear "JSON in the browser," but that is only the beginning.

Every fetch or XMLHttpRequest call that returns application/json produces JSON in the Network tab. That one is obvious. But localStorage and sessionStorage are key-value stores where both keys and values are strings, and those strings are almost always serialized JSON. Cookies frequently contain JSON-encoded data, especially session tokens and user preference objects. Chrome extensions store their data using chrome.storage.local and chrome.storage.sync, both of which serialize to JSON internally. Web Workers and Service Workers exchange messages using the structured clone algorithm, which maps closely to JSON. IndexedDB stores JavaScript objects that are JSON-compatible. And if you open a .json file directly in a Chrome tab, you get Chrome's built-in JSON renderer.

Each of these locations requires a different approach to view and inspect the JSON data. The Network tab shows you API response bodies. The Application panel shows you storage contents. The Console lets you parse, query, and transform JSON programmatically. And browser extensions can intercept and format JSON before you even see it.

Chrome DevTools Network Tab for JSON Preview

The Network tab is the first place I look whenever I need to see what an API is actually returning. Open DevTools with F12 or Cmd+Option+I on macOS, click the Network tab, and then trigger the request you want to inspect. Every HTTP request the page makes appears as a row in the request log. Our Chrome DevTools guide covers the full toolset.

Click any request that returns JSON, and Chrome opens a detail panel with several tabs. The one you want is Preview. Chrome automatically detects application/json response headers and renders the response body as a collapsible tree. You can expand and collapse objects and arrays, which makes navigating nested structures manageable even when the response is thousands of lines deep.

Filtering for JSON responses

When a page makes dozens or hundreds of requests, finding the JSON responses you care about can be tedious. The Network tab offers several filtering strategies. Click the "Fetch/XHR" filter button to show only AJAX requests, which eliminates images, stylesheets, fonts, and scripts from the list. You can also type directly in the filter box. Entering method:POST shows only POST requests. Entering status-code:200 shows only successful responses. Entering part of a URL path narrows the list to matching requests.

For API debugging specifically, I use a combination of the XHR filter and a URL path fragment. If I am working on a user profile feature and the API endpoint is /api/v2/users/profile, typing "profile" in the filter box shows only matching requests. This is significantly faster than scrolling through the full request log.

Copying JSON from the Network tab

Chrome gives you several ways to copy JSON data from a network response. Right-click the request row and you will see "Copy response" which copies the raw JSON text to your clipboard. You can also right-click inside the Preview tab and select "Copy value" on any specific node to copy just that portion of the JSON tree. For the complete request including headers, select "Copy as cURL" to get a command you can paste into a terminal to replay the request.

There is a less obvious option that I find useful regularly. Right-click the request and select "Copy as fetch." This gives you a JavaScript fetch() call with all the original headers, body, and credentials, which you can paste directly into the Console to re-execute the request and inspect the response programmatically.

Searching within large responses

Chrome's Network tab Preview does not have a built-in search for the JSON tree. If you are looking for a specific key or value inside a large API response, switch from the Preview tab to the Response tab, which shows the raw JSON text. Then press Cmd+F or Ctrl+F to open the search bar within that response. This text search works across the entire response body and highlights matches as you type. It is not as convenient as tree-based searching, but it works reliably on responses of any size.

DevTools Console for JSON Manipulation

The Console is where Chrome's JSON capabilities become genuinely powerful. While the Network tab is limited to viewing, the Console lets you parse, transform, filter, and restructure JSON using the full JavaScript language.

Parsing raw JSON strings

If you have a JSON string from any source, clipboard, log file, API documentation, paste it into the Console wrapped in JSON.parse() and Chrome gives you an interactive object you can expand and explore.

const data = JSON.parse('{"users":[{"id":1,"name":"Alice"},{"id":2,"name":"Bob"}]}');
console.table(data.users);

The console.table() method is one of the most underused tools in DevTools. Instead of rendering the data as an expandable tree, it displays it as a sortable HTML table. For arrays of objects with consistent keys, this is dramatically easier to read than the tree view. I use it constantly when debugging API responses that return lists.

Storing Network responses as variables

Here is a technique that changed how I debug APIs. In the Network tab, right-click any request and select "Store as global variable." Chrome creates a variable called temp1 (or temp2, temp3, and so on) in the Console that holds the response body as a parsed JavaScript object. You can then run any JavaScript against that data without leaving DevTools.

// After storing an API response as temp1
temp1.users.filter(u => u.role === 'admin')
temp1.users.map(u => u.email)
temp1.users.length
JSON.stringify(temp1.users[0], null, 2)

This is the fastest way I have found to explore a large API response interactively. Instead of visually scanning through a collapsed tree, I can filter, sort, map, and query the data using the array methods I already know.

Pretty printing in the Console

When you need to see a formatted version of a JSON object in the Console, JSON.stringify() with the indentation parameter is the standard approach.

// Pretty print with 2-space indentation
console.log(JSON.stringify(someObject, null, 2));

// Pretty print only specific keys
console.log(JSON.stringify(someObject, ['name', 'email', 'id'], 2));

The second argument to JSON.stringify() is a replacer, which can be either a function or an array of key names. When you pass an array, the output includes only those keys. This is useful when an object has 30 fields and you only care about three of them.

Live expression monitoring

Chrome DevTools has a "Live expressions" feature, accessible via the eye icon above the Console. You can enter a JavaScript expression and Chrome evaluates it continuously, updating the result in real time. For monitoring a value that changes, such as a localStorage key that gets updated by your application, you can enter something like JSON.parse(localStorage.getItem('userPrefs')) and watch it update without repeatedly typing the command.

Chrome DevTools Application Tab

The Application panel is where Chrome exposes all client-side storage mechanisms. For JSON specifically, the relevant sections are localStorage, sessionStorage, Cookies, IndexedDB, and Cache Storage.

localStorage and sessionStorage

Navigate to Application, then expand "Local Storage" in the left sidebar. Click your origin (domain) and Chrome shows a two-column table of all stored key-value pairs. Both keys and values are strings, and in most web applications, the values are JSON strings.

The Application panel displays these values as flat strings, which means a complex JSON object appears as a single line of unformatted text in the value column. For short values this is fine, but for anything beyond a few dozen characters, the flat string becomes unreadable. Double-click a value to edit it inline, or right-click and select "Edit value" to get a slightly larger editing area.

For a better view of JSON stored in localStorage, I switch to the Console and use the following pattern.

// View all localStorage keys
Object.keys(localStorage);

// View a specific value as formatted JSON
JSON.parse(localStorage.getItem('app_settings'));

// View all stored JSON data at once
Object.entries(localStorage).forEach(([key, value]) => {
  try {
    console.log(key, JSON.parse(value));
  } catch {
    console.log(key, value);
  }
});

The try/catch is important because not every localStorage value is valid JSON. Some values are plain strings, numbers, or other formats. The catch block handles those gracefully by logging the raw value.

Cookies with JSON values

Cookies appear under Application, then "Cookies" in the left sidebar. Chrome shows a detailed table with columns for name, value, domain, path, expiration, size, HttpOnly, Secure, SameSite, and priority. Many modern applications store JSON-encoded data in cookies, particularly for session state, user preferences, or A/B test assignments.

The cookie value column shows the raw string, which might be URL-encoded JSON. To decode and view it properly, use the Console.

// Decode a URL-encoded JSON cookie
JSON.parse(decodeURIComponent(document.cookie
  .split('; ')
  .find(c => c.startsWith('user_prefs='))
  .split('=')
  .slice(1)
  .join('=')
));

This looks verbose, and it is. The cookie API in JavaScript is famously awkward. But this pattern handles the common case of a URL-encoded JSON string stored in a named cookie. I keep a Console snippet saved for this exact pattern.

IndexedDB

IndexedDB is Chrome's structured client-side database. Under Application, expand "IndexedDB" to see all databases for the current origin. Each database contains object stores (similar to tables), and each object store contains records. Chrome renders these records as expandable JavaScript objects in the right panel.

The IndexedDB viewer in DevTools is actually one of the better JSON viewing experiences Chrome offers natively. Records are displayed as interactive objects with full expand/collapse support. You can right-click any record to copy it, delete it, or store it as a global variable for Console manipulation.

Viewing JSON Files Opened in a Chrome Tab

When you open a .json file directly in Chrome, either by dragging a file into the browser, using File > Open, or navigating to a URL that serves raw JSON, Chrome renders it with its built-in JSON viewer. As of Chrome 134, this built-in viewer provides basic syntax highlighting and a raw text display. It is functional but minimal.

The built-in viewer does not offer tree collapse/expand, search, path copying, or any form of interactive navigation. For a 20-line configuration file, it is perfectly adequate. For a 5,000-line API response dump, it is nearly useless.

What Chrome shows by default

Chrome detects that the content type is application/json (or that the file extension is .json) and renders the content with basic formatting. The output preserves the indentation from the source file and applies minimal coloring to distinguish strings, numbers, booleans, and null values. There are no interactive elements. No collapsing. No filtering. No search.

Improving the experience

If you frequently open JSON files or API endpoints in Chrome tabs, the built-in viewer's limitations become a real bottleneck. You end up copying the JSON, pasting it into an external tool, and switching back and forth between windows. That context switching adds up fast when you are debugging an issue that requires checking multiple API endpoints in sequence.

This is exactly the problem that JSON formatting extensions solve. They intercept the application/json response before Chrome's default renderer handles it and replace the static text with an interactive tree view. I will cover the best option I have found for this in the JSON formatter Pro section below.

Using chrome.storage for Extension Developers

If you build Chrome extensions, you encounter chrome.storage constantly. It is the primary way extensions persist data across browser sessions, and everything it stores is serialized as JSON internally. Viewing that data requires a different approach than regular web storage.

Inspecting extension storage

Open the extension's background page or service worker by navigating to chrome://extensions, enabling Developer Mode, and clicking "Inspect views" next to your extension. This opens a dedicated DevTools window for the extension context. From the Console in that window, you can query storage directly.

// View all local storage for the extension
chrome.storage.local.get(null, (data) => {
  console.log(JSON.stringify(data, null, 2));
});

// View sync storage
chrome.storage.sync.get(null, (data) => {
  console.log(JSON.stringify(data, null, 2));
});

// View a specific key
chrome.storage.local.get('userSettings', (data) => {
  console.table(data.userSettings);
});

The null parameter in chrome.storage.local.get(null, callback) means "get everything." This is the quickest way to dump the complete storage contents for an extension. The callback receives a plain JavaScript object, which you can inspect, stringify, or manipulate in the Console.

Storage area differences

chrome.storage.local persists to the local machine with no size limit beyond what Chrome allows (typically around 10 MB by default, configurable with the unlimitedStorage permission). chrome.storage.sync synchronizes across the user's signed-in Chrome instances but has a strict 100 KB total limit and a 8 KB per-item limit. chrome.storage.session was introduced in Manifest V3 and persists only for the browser session, similar to sessionStorage but scoped to the extension.

When debugging storage issues in extensions, the most common problem I encounter is exceeding the sync storage quota. The error message Chrome gives is not particularly descriptive. Running chrome.storage.sync.getBytesInUse(null, console.log) in the extension's Console tells you exactly how many bytes you are using out of the 102,400 byte limit.

Monitoring storage changes

Chrome's storage API fires events when values change. You can listen for these in the extension Console to monitor storage updates in real time.

chrome.storage.onChanged.addListener((changes, area) => {
  for (const [key, {oldValue, newValue}] of Object.entries(changes)) {
    console.log(`${area}.${key} changed:`);
    console.log('  Old:', JSON.stringify(oldValue, null, 2));
    console.log('  New:', JSON.stringify(newValue, null, 2));
  }
});

This listener shows every storage mutation as it happens, which is invaluable when tracking down bugs where storage values are being overwritten unexpectedly.

Working with Nested JSON and Path Navigation

Nested JSON is where most viewing tools start to struggle. A flat object with ten keys is easy to read anywhere. An object with four levels of nesting, arrays of objects within arrays, and 300 total nodes requires real tooling to navigate efficiently.

Understanding JSON paths

Every value in a JSON document has a unique path from the root. These paths are expressed using dot notation for object properties and bracket notation for array indices. For example, in the following structure, the phone number "555-0102" lives at the path users[1].contacts.phone.

{
  "users": [
    {
      "name": "Alice",
      "contacts": {
        "phone": "555-0101",
        "email": "alice@example.com"
      }
    },
    {
      "name": "Bob",
      "contacts": {
        "phone": "555-0102",
        "email": "bob@example.com"
      }
    }
  ]
}

Knowing the path to a value matters for several practical reasons. When you write code that extracts data from an API response, the path is what your code navigates. When you file a bug report about incorrect data, the path tells the backend developer exactly which field is wrong. When you build a JSON transformation pipeline, paths define the mapping between input and output.

Navigating nested structures in DevTools

In the Network tab Preview, Chrome renders nested JSON as a collapsible tree. Click the triangle next to any object or array to expand it. The tree remembers your expand/collapse state, so you can open the branches you care about and leave the rest closed.

For programmatic navigation, the Console gives you JavaScript's full object traversal capabilities.

// Assuming the API response is stored as temp1
temp1.users[1].contacts.phone  // "555-0102"

// Optional chaining for safe navigation
temp1?.users?.[1]?.contacts?.phone

// Find all phone numbers
temp1.users.map(u => u.contacts.phone)

// Find users where phone starts with "555-01"
temp1.users.filter(u => u.contacts.phone.startsWith('555-01'))

Extracting paths from complex documents

When I am dealing with a deeply nested API response for the first time and I need to understand its shape, I use a recursive function in the Console that prints all paths and their types.

function printPaths(obj, prefix = '') {
  for (const [key, value] of Object.entries(obj)) {
    const path = prefix ? `${prefix}.${key}` : key;
    if (value && typeof value === 'object' && !Array.isArray(value)) {
      printPaths(value, path);
    } else if (Array.isArray(value)) {
      console.log(`${path}[] (${value.length} items)`);
      if (value.length > 0 && typeof value[0] === 'object') {
        printPaths(value[0], `${path}[0]`);
      }
    } else {
      console.log(`${path} = ${typeof value}`);
    }
  }
}

printPaths(temp1);

This outputs every leaf path in the document along with its type, which gives me a complete map of the data structure in seconds. It is faster than manually expanding every branch in the tree view, especially for documents with dozens of fields per object.

Advanced Techniques for JSON in Chrome

Console snippets for repeated tasks

Chrome DevTools lets you save JavaScript snippets under Sources, then Snippets. These persist across sessions and work on any page. I keep a collection of JSON utility snippets that I run regularly.

// Snippet: "Dump all localStorage as formatted JSON"
const allData = {};
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  try {
    allData[key] = JSON.parse(localStorage.getItem(key));
  } catch {
    allData[key] = localStorage.getItem(key);
  }
}
copy(JSON.stringify(allData, null, 2));
console.log('All localStorage copied to clipboard');

The copy() function is a DevTools-specific API that copies a string to the system clipboard. Combined with JSON.stringify(), it gives you a one-command way to extract formatted JSON from any data source in the browser and paste it into an editor, a Slack message, or a bug report.

Network tab HAR export for JSON analysis

If you need to capture all API responses from a session for offline analysis, the Network tab supports HAR (HTTP Archive) export. Right-click anywhere in the request list and select "Save all as HAR with content." This produces a JSON file (the HAR format is itself JSON) containing every request and response, including headers, timing, and response bodies. You can then process this file with jq, Python, or any JSON tool to extract the data you need.

# Extract all JSON response bodies from a HAR file
cat session.har | jq '.log.entries[]
  | select(.response.content.mimeType == "application/json")
  | {url: .request.url, body: .response.content.text}'

Overriding API responses for testing

Chrome DevTools lets you override network responses without modifying your server. In the Sources panel, set up a local override folder. Then in the Network tab, right-click any request and select "Override content." Chrome saves the response body to your local file system and serves your modified version on subsequent requests. This is incredibly useful for testing how your frontend handles different JSON structures, edge cases, or error responses.

For example, if you want to test how your UI handles an empty array in the users field, override the API response to return {"users": []} instead of the real data. The override persists across page reloads until you disable it, so you can test thoroughly without touching the backend.

Using the Performance tab to find slow JSON parsing

If your application parses large JSON payloads and you suspect it is causing performance issues, the Performance tab can confirm it. Record a performance profile during the JSON parsing operation. In the flame chart, look for JSON.parse calls. Chrome shows exactly how long each parse operation takes. If you see a JSON.parse call taking more than 50ms, you are blocking the main thread long enough to cause noticeable UI jank.

The fix for slow JSON parsing depends on the situation. For API responses, consider paginating to reduce payload size. For local data, consider using IndexedDB instead of parsing a large JSON blob from localStorage on every page load. For truly large datasets, consider streaming JSON parsers or Web Workers to move the parsing off the main thread.

Common JSON Viewing Pitfalls

Truncated previews

Chrome's Network tab Preview truncates very long strings and very large arrays. If a response contains a 50,000-character string value or an array with 10,000 elements, the Preview tab might show only a portion. The Response tab always shows the complete content, so switch to it when you suspect truncation.

Encoding issues

JSON supports Unicode, but some servers return JSON with incorrect content-type headers, BOM (Byte Order Mark) characters, or non-UTF-8 encodings. When Chrome shows garbled characters in a JSON response, check the response headers for the charset declaration. If it says charset=iso-8859-1 but the data contains UTF-8 encoded characters, you will see encoding artifacts. This is a server-side problem, but knowing where to look saves debugging time.

JSONP responses

Some older APIs return JSONP (JSON with Padding) instead of plain JSON. A JSONP response wraps the JSON data in a function call, like callback({"data": "value"}). Chrome's JSON preview does not handle JSONP. The content-type is usually application/javascript rather than application/json, so auto-detection also fails. To extract the JSON from a JSONP response, use the Console to strip the function wrapper.

// Extract JSON from a JSONP string
const jsonp = 'callback({"users": [1, 2, 3]})';
const json = jsonp.slice(jsonp.indexOf('(') + 1, jsonp.lastIndexOf(')'));
const data = JSON.parse(json);

Content Security Policy blocking extensions

Some websites set strict Content Security Policy headers that prevent browser extensions from injecting scripts into the page. When this happens, a JSON formatting extension might fail silently on specific domains. If JSON Formatter Pro or any other extension does not activate on a particular page, check the Console for CSP violation errors. The workaround is to copy the JSON and open it in a new blank tab, or use the DevTools Console approach instead.

Frequently Asked Questions

How do I view JSON in Chrome without an extension

Open DevTools with F12, go to the Network tab, click the request that returns JSON, and select the Preview tab. Chrome renders the response as a collapsible tree. For JSON files, you can open them directly in a Chrome tab and Chrome will apply basic syntax highlighting. For JSON strings in localStorage or cookies, use the Console with JSON.parse() to view them as interactive objects.

What is the best Chrome extension for viewing JSON

I recommend JSON Formatter Pro. It auto-detects JSON on any page, provides a collapsible tree view with syntax highlighting, includes search functionality, and handles large documents well. It has a 4.79-star rating and does not require invasive permissions.

Why does Chrome show JSON as plain text

Chrome displays JSON as plain text when the server does not set the correct Content-Type: application/json header. Some servers return JSON with text/plain or text/html headers, which prevents Chrome's JSON detection from activating. A JSON formatting extension like JSON Formatter Pro can detect JSON content regardless of the content-type header, which solves this problem.

How do I copy a JSON path in Chrome DevTools

Chrome DevTools does not have a built-in "copy JSON path" feature in the Network tab Preview. You can manually trace the path by looking at the tree structure, or use a Console snippet to enumerate all paths programmatically. JSON Formatter Pro includes path copying in its tree view, which makes this a one-click operation.

Can I edit JSON in Chrome DevTools

You can edit JSON values in localStorage and sessionStorage directly through the Application panel by double-clicking any value. For API responses, you can use the Sources panel Overrides feature to modify response bodies. For real-time manipulation, use the Console to parse JSON, modify the resulting object, and serialize it back with JSON.stringify().

How do I view JSON stored in localStorage

Open DevTools, go to the Application tab, expand "Local Storage" in the sidebar, and click your site's origin. Chrome shows all key-value pairs. For a formatted view of JSON values, use the Console with JSON.parse(localStorage.getItem('yourKey')) to see the data as an expandable object, or console.table() for tabular data.

How do I handle large JSON files in Chrome

For files under 5 MB, JSON Formatter Pro handles rendering well. For larger files, use the DevTools Console to store the data as a variable and query specific portions with JavaScript. For files over 10 MB, switch to a command-line tool like jq, which processes JSON in a streaming fashion with constant memory usage. Chrome's built-in Preview tab can handle moderately large responses but may become slow above a few megabytes.

What is the difference between JSON preview and response in Chrome Network tab

The Preview tab renders JSON as an interactive, collapsible tree with syntax highlighting. The Response tab shows the raw text as it was received from the server. Preview is better for exploration and understanding structure. Response is better for text search, copying the complete content, and verifying the exact bytes the server returned. Some very large responses may be truncated in Preview but complete in Response.

How do I debug JSON parse errors in Chrome

When JSON.parse() fails, Chrome throws a SyntaxError with a message indicating the character position where parsing failed. The format is typically "Unexpected token X in JSON at position Y." Count Y characters from the start of your JSON string to find the problem location. Common causes include trailing commas, single quotes, unquoted keys, and embedded comments. Paste the problematic JSON into the Console and Chrome will show the exact error position.

Does Chrome support JSON5 or JSONC

Chrome's JSON.parse() only supports standard JSON as defined in RFC 8259. It does not support JSON5 features like comments, trailing commas, or single-quoted strings. VS Code uses JSONC for its settings files, but this is a VS Code-specific parser. If you need to view JSON5 or JSONC in Chrome, you need to strip the non-standard features first or use a dedicated parser library like the json5 npm package.

JSON shows up in more places inside Chrome than most developers realize. Between the Network tab, Console, Application panel, and a focused extension like JSON Formatter Pro, you have a complete toolkit for viewing, searching, and manipulating JSON data without ever leaving the browser. The key is knowing which tool to reach for in each situation, and this guide should give you that map.
