About This Tool

The Sitemap Validator is a free browser-based tool created by Michael Lip that checks your XML sitemap against the official sitemaps.org protocol specification. It detects structural errors, invalid dates, duplicate URLs, missing required elements, and protocol violations that could prevent search engines from properly indexing your site.

What Is a Sitemap?

A sitemap is an XML file hosted on your website that provides search engines with a structured list of every page you want indexed. Think of it as a roadmap — it tells crawlers like Googlebot, Bingbot, and others exactly where to look and how often those pages change.

The sitemap protocol was jointly developed by Google, Yahoo, and Microsoft in 2006 and later standardized at sitemaps.org. It supports two root formats: <urlset> for regular sitemaps and <sitemapindex> for sitemap index files that reference multiple sitemaps.

Every URL entry in a sitemap can include optional metadata like the last modification date (<lastmod>), change frequency (<changefreq>), and a priority value (<priority>) between 0.0 and 1.0. While these optional fields don't guarantee anything about crawl behavior, they give search engines useful hints.

Why You Should Validate Your Sitemap

A broken sitemap is worse than no sitemap at all. If your XML is malformed, search engines will simply ignore it — and you won't get an error message about it in most cases. This means pages you care about might not get discovered or re-crawled on a useful schedule.

Common issues include missing the required XML namespace declaration, forgetting the <loc> tag inside a URL entry, or using invalid date formats in <lastmod>. Some CMS plugins generate sitemaps automatically but produce subtly broken output — an unclosed tag here, a malformed URL there.

Validation catches these problems before they affect your search visibility. Run your sitemap through a validator after every significant change to your site structure, and especially after switching CMS platforms, migrating domains, or updating sitemap generation plugins.

The Sitemaps.org Protocol Explained

The protocol defines a strict XML schema. The root element must be <urlset> with the namespace xmlns="http://www.sitemaps.org/schemas/sitemap/0.9". Inside it, each page is wrapped in a <url> element.

Required Elements

<loc> — The full URL of the page. This is the only required child element of <url>. It must be a properly encoded absolute URL starting with http:// or https://.

Optional Elements

<lastmod> — The date the page was last modified, in ISO 8601 format. Acceptable formats include YYYY-MM-DD, YYYY-MM-DDThh:mmTZD, and full datetime with seconds.

<changefreq> — A hint about how frequently the page changes. Valid values are: always, hourly, daily, weekly, monthly, yearly, never. Google has publicly stated they largely ignore this field, but other engines may still use it.

<priority> — A value between 0.0 and 1.0 indicating the relative importance of a URL compared to other URLs on the same site. The default is 0.5. This is a suggestion, not a directive.

Common Sitemap Errors and How to Fix Them

Missing XML declaration or namespace: Always start your sitemap with <?xml version="1.0" encoding="UTF-8"?> and include the correct xmlns attribute on the root element.

Invalid lastmod dates: Use ISO 8601 format. A common mistake is writing 01/15/2024 instead of 2024-01-15. Timestamps with timezone offsets like 2024-01-15T09:30:00+00:00 are also valid.

Exceeding the 50,000 URL limit: A single sitemap file can contain at most 50,000 URLs. For larger sites, split into multiple sitemap files and reference them from a sitemap index file.

Relative URLs in loc: The <loc> element must contain a full absolute URL including the protocol. Writing /page.html instead of https://example.com/page.html will cause validation failures.

Duplicate URLs: Each URL should appear only once in a sitemap. Duplicates waste your URL budget and can confuse crawlers about which entry's metadata to trust.

Priority values out of range: Priority must be a decimal between 0.0 and 1.0 inclusive. Values like 2 or -0.5 are invalid.

Working with Sitemap Index Files

When your site has more than 50,000 URLs — or when you want to organize sitemaps by content type — a sitemap index file is the solution. Instead of <urlset>, the root element is <sitemapindex>, and each entry uses <sitemap> instead of <url>.

Each <sitemap> entry requires a <loc> pointing to the individual sitemap file and optionally a <lastmod> date. The index file itself must also respect the 50MB size limit and should be referenced in your robots.txt file.

This validator handles both formats. It detects whether your XML uses <urlset> or <sitemapindex> as the root element and applies the appropriate validation rules for each.

Sitemap Best Practices for SEO

Keep it current. Update your sitemap whenever you add, remove, or significantly modify pages. Stale sitemaps with outdated lastmod dates can reduce crawl efficiency.

Only include canonical URLs. Every URL in your sitemap should be the canonical version of that page. Don't list URLs that redirect, return 404, or have a different canonical tag.

Reference it in robots.txt. Add a Sitemap: https://yoursite.com/sitemap.xml directive to your robots.txt file so crawlers can find it automatically.

Use UTF-8 encoding. The XML declaration should specify UTF-8, and all URLs should be properly entity-encoded. Ampersands become &amp;, for example.

Submit to Google Search Console. While Google can discover your sitemap from robots.txt, manually submitting it through Search Console confirms Google has received it and lets you monitor its processing status.

Monitor regularly. Automated sitemap generation can break silently. Schedule periodic validation checks — monthly at minimum — to catch issues before they affect your indexing.

Frequently Asked Questions

What is a sitemap and why does it need validation?

A sitemap is an XML file that lists the URLs on your website so search engines can crawl them efficiently. Validation confirms the file follows the sitemaps.org protocol, meaning search engines can parse it without errors. A malformed sitemap may be silently ignored.

What are the limits for a single sitemap file?

According to the sitemaps.org protocol, a single sitemap file can contain a maximum of 50,000 URLs and must not exceed 50MB uncompressed. If you exceed these limits, split your sitemap into multiple files and use a sitemap index.

What is a sitemap index file?

A sitemap index file lists multiple sitemap files. It uses the <sitemapindex> root element instead of <urlset> and contains <sitemap> entries each with a <loc> pointing to an individual sitemap file.

Is my sitemap data sent to a server?

No. All validation happens entirely in your browser using JavaScript. Your sitemap data never leaves your device and is not uploaded to any server.

What elements are required in a sitemap?

The root element must be <urlset> with the proper xmlns attribute. Each <url> entry must contain a <loc> element with a valid URL. Optional elements include <lastmod>, <changefreq>, and <priority>.
