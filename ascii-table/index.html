Control Characters (0-31)

The first 32 ASCII codes (0-31) are control characters. They were designed for early telecommunications equipment and teletypewriters. Most originated from the needs of the Teletype Model 33, which was the most common terminal when ASCII was standardized in 1963. While many are now obsolete, several remain critical in modern computing.

Line Ending Conventions

The CR and LF characters are the source of one of computing's most persistent compatibility issues. Different operating systems use different line endings:

  • Unix/Linux/macOS: LF only (0x0A, \n)
  • Windows: CR+LF (0x0D 0x0A, \r\n)
  • Classic Mac OS (pre-OS X): CR only (0x0D, \r)

This dates back to teletypewriters, where CR moved the print head to the left margin and LF advanced the paper one line. They were separate mechanical operations. Unix simplified to just LF, while Windows preserved the two-character sequence. This difference still causes issues when transferring files between systems, which is why modern editors and version control systems handle line ending conversion automatically.

Printable Characters (32-126)

The 95 printable ASCII characters (codes 32-126) include the space character, 26 uppercase letters, 26 lowercase letters, 10 digits, and 32 punctuation and symbol characters. These are the characters you see on a standard US English keyboard.

A key design feature: uppercase and lowercase letters differ by exactly 32 (one bit). 'A' is 65, 'a' is 97. This was intentional, making case conversion a single bit operation (toggle bit 5). In binary, 'A' is 1000001 and 'a' is 1100001. The only difference is the sixth bit. This elegant design choice by the ASCII committee made case-insensitive comparison and conversion trivially efficient on early hardware.

Similarly, the digit characters '0' through '9' have codes 48-57. To convert a digit character to its numeric value, you just subtract 48 (or 0x30). This is another deliberate design decision that simplifies parsing in code.

History of ASCII

ASCII was developed during the early 1960s as the telecommunications industry needed a standard character encoding to replace the various incompatible codes used by different manufacturers. The work was led by a committee of the American Standards Association (now ANSI), with significant input from Bob Bemer, who is often called the "father of ASCII."

The first version was published in 1963 as ASA X3.4-1963. It went through several revisions, with the most significant change being the addition of lowercase letters in the 1967 revision (the original 1963 version had uppercase only in positions 96-127, which were later reassigned). The final version, ANSI X3.4-1986, is the standard we use today.

Key design decisions that shaped ASCII:

  • 7-bit encoding: The committee chose 7 bits (128 characters) as a compromise. Some members wanted 6 bits (64 characters), others wanted 8 (256). The 7-bit choice left room for control characters while keeping the code compact enough for the telecommunications equipment of the era.
  • Control characters first: Placing control codes at positions 0-31 meant they had lower values than printable characters, which simplified sorting and comparison operations.
  • Letters in alphabetical order: Both uppercase (65-90) and lowercase (97-122) letters are in sequential order, making alphabetic operations (sorting, case conversion) simple arithmetic.
  • 32-offset between cases: The 32-position gap between uppercase and lowercase (A=65, a=97) corresponds to a single bit difference, enabling efficient case conversion through bit manipulation.
  • Digits 0-9 at 48-57: Digit characters are 48 above their numeric value, so subtracting 48 (or 0x30) converts a digit character to its integer value.

Before ASCII, different computer manufacturers used their own encodings. IBM used EBCDIC, which had non-contiguous letter ranges (making string operations much harder). The Baudot code used 5 bits and required shift characters to switch between letters and figures. ASCII's clean, logical design was a major improvement and quickly became the dominant encoding.

ASCII and Unicode

Unicode is the modern standard for character encoding, supporting over 149,000 characters from virtually every writing system in the world. The critical relationship between ASCII and Unicode is that the first 128 Unicode code points (U+0000 to U+007F) are identical to ASCII. This was a deliberate design choice to ensure backward compatibility.

UTF-8: The Bridge

UTF-8, the most common Unicode encoding on the web (used by over 98% of websites according to W3Techs), is also backward-compatible with ASCII. Any valid ASCII text is also valid UTF-8. Characters 0-127 are encoded as a single byte in UTF-8, identical to their ASCII representation. Characters above 127 use 2-4 bytes.

The practical implication: if your text is pure ASCII (codes 0-127), you do not need to worry about encoding issues. The text will be correctly interpreted whether the system reads it as ASCII, UTF-8, Latin-1, or most other encodings. Encoding problems only arise when you use characters outside the ASCII range.

Programming Usage

Here is how to work with ASCII values in the most common programming languages.

Python

# Character to ASCII code ord('A') # Returns 65 ord('a') # Returns 97 ord('0') # Returns 48 # ASCII code to character chr(65) # Returns 'A' chr(10) # Returns '\n' # Convert string to list of codes [ord(c) for c in "Hello"] # [72, 101, 108, 108, 111] # Case conversion via ASCII math chr(ord('a') - 32) # 'A' (lowercase to uppercase) chr(ord('A') + 32) # 'a' (uppercase to lowercase)

JavaScript

// Character to ASCII code 'A'.charCodeAt(0) // 65 'Hello'.charCodeAt(1) // 101 (e) // ASCII code to character String.fromCharCode(65) // 'A' String.fromCharCode(72,101,108,108,111) // 'Hello' // Convert string to array of codes [...'Hello'].map(c => c.charCodeAt(0)) // [72, 101, 108, 108, 111]

C / C++

// Characters ARE their ASCII values in C char c = 'A'; // c == 65 int code = (int)'A'; // code == 65 char ch = (char)65; // ch == 'A' // Check if character is a digit if (c >= '0' && c <= '9') { ... } // Convert digit char to int int digit = c - '0'; // '7' - '0' = 55 - 48 = 7 // Case conversion char lower = c | 0x20; // to lowercase (set bit 5) char upper = c & 0xDF; // to uppercase (clear bit 5) char toggle = c ^ 0x20; // toggle case (flip bit 5)

Character Patterns and Tricks

The ASCII table has several useful patterns that make character manipulation efficient in code. These patterns were intentional design decisions by the original ASCII committee.

PatternHow It WorksExample
Case differs by bit 5 (32)'a' XOR 0x20 = 'A'97 XOR 32 = 65
Digits are 0x30 + value'5' - '0' = 553 - 48 = 5
Control chars = letter + 0x40Ctrl+A = 0x01, A = 0x411 + 64 = 65
Letters are alphabetical'C' - 'A' = 2 (position in alphabet)67 - 65 = 2
Printable chars start at 0x20c >= 0x20 means printable32 = space
DEL is 0x7F (all bits set)01111111 in binaryUsed to "erase" on paper tape

The Ctrl key relationship is particularly interesting. Ctrl+A produces ASCII 1, Ctrl+B produces ASCII 2, all the way to Ctrl+Z producing ASCII 26. The mapping is simple: Ctrl+letter = letter code - 64 (or equivalently, clear bits 5 and 6). This is why Ctrl+C (ASCII 3, ETX/End of Text) interrupts programs, Ctrl+D (ASCII 4, EOT/End of Transmission) signals end-of-input in Unix, and Ctrl+G (ASCII 7, BEL) rings the terminal bell.

Frequently Asked Questions

What is ASCII?

ASCII (American Standard Code for Information Interchange) is a character encoding standard published in 1963 that assigns numeric values (0-127) to 128 characters, including English letters, digits, punctuation marks, and control characters. It uses 7 bits per character and became the foundation for all modern text encoding systems. UTF-8, the dominant web encoding, is backward-compatible with ASCII.

How many characters are in ASCII?

Standard ASCII defines 128 characters using 7 bits (values 0-127). This includes 33 control characters (0-31 and 127), a space character (32), and 94 other printable characters (33-126) covering letters, digits, and punctuation. Extended ASCII uses an 8th bit for 128 additional characters (128-255), but those vary by code page and are not part of the official standard.

What is the difference between ASCII and Unicode?

ASCII encodes 128 characters (English only) using 7 bits. Unicode encodes over 149,000 characters from virtually every writing system, including emoji. The first 128 Unicode code points are identical to ASCII, ensuring backward compatibility. UTF-8 (the most common Unicode encoding) represents ASCII characters as a single byte, identical to their ASCII encoding.

What are ASCII control characters?

Control characters (codes 0-31 and 127) are non-printable characters originally for controlling teletypewriters and communication equipment. Commonly used ones today include NUL (0, string terminator), TAB (9), LF (10, newline), CR (13, carriage return), and ESC (27, ANSI escape sequences). Most others are obsolete but remain defined in the standard.

What is the ASCII code for the letter A?

Uppercase 'A' is ASCII 65 (0x41 hex, 0101 octal, 01000001 binary). Lowercase 'a' is 97 (0x61 hex). The difference of 32 between upper and lowercase corresponds to a single bit (bit 5), which was an intentional design choice enabling efficient case conversion through bit manipulation.

How do I convert text to ASCII codes?

Use the converter tool above, or in code: Python uses ord('A') returning 65, JavaScript uses 'A'.charCodeAt(0), and C/C++ treats characters as their ASCII values directly (char c = 'A'; is the same as char c = 65;). For bulk conversion, map over each character in the string.

Why does ASCII start at 0?

ASCII starts at 0 because computers count in binary starting from 0. The value 0000000 (7 bits) is the first possible code point. The NUL character at position 0 serves an important purpose as the string terminator in C and related languages. Starting at 0 also means character arithmetic works naturally (digit '0' at code 48, so subtracting 48 gives the numeric value).

What is Extended ASCII?

Extended ASCII refers to 8-bit character sets that define 128 additional characters (codes 128-255) beyond standard ASCII. Unlike standard ASCII which is universal, extended ASCII varies by code page. ISO 8859-1 (Latin-1) covers Western European languages, Windows-1252 adds typographic characters, and IBM Code Page 437 includes box-drawing characters. Today, UTF-8 has largely replaced extended ASCII.
